# รอบ 2F — ทำให้คำสัญญาของเกมเป็นจริง

> สัญญาที่ทุกคนยึดในรอบนี้ | PM เป็นเจ้าของ | 22 ก.ย. 2026
> **รอบนี้ไม่เพิ่มฟีเจอร์ใหม่แม้แต่อย่างเดียว** มีแต่การแก้สิ่งที่รอบ 2T พิสูจน์ว่าพัง

---

## 1. โจทย์

รอบ 2T ปล่อยผู้เล่นสามคนลงเล่นจริงจนจบ ผลคือ:

> คนที่เขียน `attack(weakest(enemies))` บรรทัดเดียวแล้วไม่แก้อีกเลย **จบเกมทั้งแผนที่**

เกมนี้สัญญากับผู้เล่นว่า "โค้ดดีขึ้นแล้วผ่าน" ตอนนี้สัญญานั้นเป็นเท็จ
และทุกอย่างที่สร้างมาหกรอบ — ภาษา เอดิเตอร์ ภูมิภาค บทเรียน การดวล — วางอยู่บนมันทั้งหมด

**รอบนี้จึงมีเป้าหมายเดียว: ทำให้คนที่ไม่คิดตันจริง**
ไม่ใช่ทำให้เกมยากขึ้น — เกมยากขึ้นเฉย ๆ แก้ไม่ได้ เพราะคนไม่คิดจะแค่ฟาร์มนานขึ้น

---

## 2. กฎเหล็กของรอบนี้

**ห้ามแก้ด้วยการเพิ่มตัวเลขความยาก** ถ้าคำตอบของข้อไหนคือ "คูณ HP มอนอีก 1.3 เท่า"
แปลว่ายังไม่เจอสาเหตุจริง — มอนแรงขึ้นทำให้คนไม่คิดต้องฟาร์มเพิ่ม 3 เลเวล
แล้วก็ผ่านอยู่ดี ส่วนคนที่คิดก็โดนลงโทษเท่ากัน

สิ่งที่ต้องเปลี่ยนคือ **ความสัมพันธ์ระหว่าง "เวลาที่ลงไป" กับ "ความคืบหน้า"**
ไม่ใช่ขนาดของตัวเลข

---

## 3. สี่ข้อที่ต้องแก้ (เรียงตามน้ำหนักที่วัดได้จากรอบ 2T)

### 3.1 การฟาร์มต้องหยุดได้ผล — คันโยกที่ใหญ่ที่สุด

**สิ่งที่วัดได้:** แพ้ชั้น 8 ได้ 1,728 EXP · ชนะชั้น 8 ได้ 2,203 EXP
ไม่มีค่าปรับ ไม่มีคูลดาวน์ → วงจรของคนไม่คิดคือ "แพ้ → ถอยไปฟาร์มชั้นเก่า → กลับมาชนะ"

**ต้องแก้สองทาง พร้อมกัน:**

1. **เนื้อหาที่ต่ำกว่าตัวเรามาก ต้องให้รางวัลน้อยลงอย่างชัดเจน**
   นี่คือข้อหลัก — มันตัดวงจร "ถอยไปฟาร์ม" ที่ปลายทาง ไม่ใช่ที่ทางเข้า
   สูตรอยู่ใน `gamedata.balance` ปรับได้โดยไม่แตะโค้ด

2. **แพ้ต้องได้น้อยกว่าชนะอย่างรู้สึกได้ และได้ตามสัดส่วนเวฟที่ผ่าน**
   แพ้ตั้งแต่เวฟ 2 กับแพ้ที่เวฟ 9 ต้องไม่เท่ากัน — อย่างหลังคือ "เกือบแล้ว" ซึ่งควรได้มากกว่า

**ห้ามทำ:** ตัด EXP ตอนแพ้เป็นศูนย์ · หักเลเวล · หักของ · ใส่คูลดาวน์เวลาจริง
เหตุผล: ผู้เล่นเป้าหมายคือเด็กที่กำลังหัดเขียนโปรแกรม การลงโทษความล้มเหลวแรง ๆ
สอนให้เลิกลอง ซึ่งตรงข้ามกับสิ่งที่เกมนี้มีไว้เพื่อสอน — เราต้องการให้ *การฟาร์ม*
เลิกได้ผล ไม่ใช่ให้ *การแพ้* เจ็บ

### 3.2 ความคืบหน้าต้องแยกรายภูมิภาค

**สิ่งที่วัดได้:** เคลียร์หอคอยชั้น 9 แล้ว หมู่เกาะ · ซากปรักหักพัง · ดินแดนน้ำแข็ง
กลายเป็น `completed: true` ทั้งที่ไม่เคยกดเข้าไปเลย (ทั้ง `lazy` และ `diligent` เจอตรงกัน)

สาเหตุ: `regionProgress()` คิดจาก `highest_floor` ตัวเดียว
ผลคือบทเรียนของทุกโซนอยู่นอกเส้นทางหลัก**โดยโครงสร้าง** — รอบ 2W เป็นโมฆะทั้งรอบ

**ต้องแก้เป็น:** ตารางความคืบหน้าต่อ (ผู้เล่น × ภูมิภาค)
**แต่ยังคงกฎ "ตันที่หนึ่งมีที่อื่นให้ไป" ไว้:** การ *ปลดล็อก* โซนยังใช้ `highest_floor`
เหมือนเดิม เปลี่ยนแค่ว่าการ *เคลียร์* ต้องเล่นโซนนั้นจริง

PM เขียนกฎเดิมไว้เองในรอบ 2W โดยตั้งใจ — และคิดไม่ครบว่ามันแปลว่า
"ไม่ต้องไปที่ไหนเลยก็ได้ทุกที่" บันทึกความผิดพลาดนี้ไว้ในเอกสารรอบ 2W ด้วย

### 3.3 ครึ่งหนึ่งของภาษาเปิดไม่ได้จริง

```
arith (+ - * /) และ len()   ปลดล็อกชั้น 13   ← ชั้นสูงสุดของเกมคือ 10
for                         ปลดล็อกชั้น 10   ← ชั้นสุดท้ายพอดี
```

ผู้เล่นเห็น "ต้องผ่านชั้น 13 ก่อน" ซึ่งเกมทำให้ไม่ได้ และ `diligent` ต้องฮาร์ดโค้ด
`d.hp > 300` แทนที่จะเขียน `me.atk * 1.5` เพราะเหตุนี้

**ต้องแก้:** ไล่บันไดการปลดล็อกใหม่ให้ **ทุกค่าไปถึงได้จริง** และกระจายทั้งช่วง 1–10
**และต้องมีเทสต์ที่ทำให้ความผิดพลาดแบบนี้ซ้ำไม่ได้อีก** — เทสต์ที่ยืนยันว่า
ทุกค่าใน `FEATURE_UNLOCK` (ยกเว้นตัวที่จงใจปิดด้วย 999) ต้อง ≤ ชั้นสูงสุดของเกม
เทสต์นั้นสำคัญกว่าตัวเลขที่เลือก เพราะตัวเลขปรับได้ แต่กับดักนี้ต้องปิดถาวร

### 3.4 เขียนผิดแล้วเกมต้องบอก

PM ยิงเข้าล่ามเองแล้ว ยืนยันทั้งหมดนี้ **ไม่มี error ไม่มี warning**:

| เขียนแบบนี้ | เกิดอะไรจริง |
|---|---|
| `attack(me)` | `{"action":"attack","targetId":"__self__"}` แล้วในสนามไปโดนศัตรู |
| `defend()` แล้วบรรทัดถัดมา `attack(...)` | ได้แค่ `defend` บรรทัดที่สองหายเงียบ ๆ |
| `for e in enemies: attack(e)` | ตีครั้งเดียว |
| `cast("heal", ...)` ทั้งที่ไม่มีสกิลนั้น | ผ่าน แล้วร่ายจริงในสนาม |
| `has_buff("bananas")` | ผ่าน เป็นเท็จตลอดกาล |

ในเกมสอนเขียนโปรแกรม **ความผิดพลาดแบบเงียบแย่กว่า error** เพราะผู้เล่นเรียนสิ่งที่ผิด
โดยไม่มีอะไรขัด · ทุกข้อข้างบนต้องกลายเป็น error หรือ warning ที่บอกวิธีแก้

เพิ่มอีกข้อจากบันทึกของ `newbie`:
**`NameError` ของฟังก์ชันต้องลิสต์ฟังก์ชันที่ใช้ได้** เหมือนที่ `NameError` ของตัวแปร
ลิสต์ `me, enemies, allies, turn_no` อยู่แล้ว — ตอนนี้มันบอกให้ "ดูหน้าช่วยเหลือ"
ซึ่งไม่มีอยู่จริง `newbie` ต้องยัดชื่อที่เดา 35 ชื่อลงโปรแกรมเดียวเพื่อค้นว่ามีฟังก์ชัน 8 ตัว
**นี่คือการแก้ที่ถูกที่สุดและได้ผลมากที่สุดในเอกสารทั้งฉบับ**

## 4. สิ่งที่ยัง *ไม่* แก้ในรอบนี้ และทำไม

- **อุปกรณ์โตเร็วกว่าโค้ด** (`diligent` วัดได้ว่าใส่ของ+อัปเกรดคุ้มกว่าการแก้โปรแกรมทุกเวอร์ชันรวมกัน)
  ข้อนี้จริงและสำคัญ แต่ **ยังไม่รู้ว่าสาเหตุคือของแรงไป หรือเพราะเกมไม่เคยบอกให้ใส่ของ**
  (`diligent` เดินถึงชั้น 9 โดยใส่ไม้เท้าเวทของชั้น 1 และมีของดีค้างในกระเป๋า 44 ชิ้น)
  **ต้องวัดก่อนแก้** — เดาแล้วปรับตัวเลขคือสิ่งที่กฎเหล็ก §2 ห้ามไว้
- บทเรียนของโซนที่ผิด/ไม่จำเป็น 4 ใน 6 โซน — รอ §3.2 ลงก่อน เพราะตอนนี้โซนยังไม่ถูกบังคับให้เล่น
  การเขียนบทเรียนใหม่ตอนนี้คือการเขียนของที่ยังไม่มีใครต้องอ่าน
- กระเป๋าไม่มีเพดาน · เลือกอาชีพช้าไป 4 เลเวล · `mdef` เป็นทศนิยม — จดไว้ ไม่ใช่รอบนี้

## 5. เกณฑ์รับงาน — เอาการเล่นทดสอบกลับมาเป็นเทสต์

| # | เกณฑ์ | วัดยังไง |
|---|---|---|
| **F1** | **`attack(weakest(enemies))` บรรทัดเดียวต้องตันจริง** | ปล่อย `lazy` ตัวใหม่ลงเล่นซ้ำด้วยกติกาเดิมทุกข้อ แล้ววัดว่าตันที่ชั้นไหน เลเวลเท่าไร |
| **F2** | คนที่เขียนเงื่อนไขเป็นต้องไปได้ไกลกว่าอย่างชัดเจน | โปรแกรมที่ดีกว่าต้องผ่านชั้นที่ F1 ตัน ที่เลเวลไม่สูงกว่า |
| **F3** | เคลียร์โซนหนึ่งแล้วโซนอื่นต้องไม่ขึ้น `completed` เอง | ยิง API จริง: เคลียร์หอคอยจนจบ แล้วเช็กว่าภูมิภาคอื่นยังเป็น 0 |
| **F4** | ทุกค่าใน `FEATURE_UNLOCK` ไปถึงได้ และมีเทสต์กันไว้ | `npm test -w engine` ต้องมีเทสต์ที่ตกถ้าใครตั้งค่าเกินชั้นสูงสุด |
| **F5** | ห้าอาการเงียบใน §3.4 กลายเป็น error/warning ที่บอกวิธีแก้ | ยิงเข้าล่ามทีละเคส |
| **F6** | `npm run tune -w engine` ยังผ่าน B1–B5 ครบ | ของเดิมต้องไม่พังเพราะการแก้รอบนี้ |
| **F7** | เซฟของผู้เล่นเดิมต้องไม่เสียหาย | migration รันทับ `server/data.db` ของจริงแล้วข้อมูลครบ |

**F1 คือเกณฑ์จริงของรอบนี้** ที่เหลือคือเงื่อนไขที่ทำให้ F1 มีความหมาย
ถ้า F1 ไม่ผ่าน รอบนี้ไม่ผ่าน ไม่ว่าข้ออื่นจะเรียบร้อยแค่ไหน
