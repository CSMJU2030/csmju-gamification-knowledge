Code Tower
โครงหน้าจอหลัก 3 หน้า

ส่งให้ PL ตรวจโครงก่อนลงสี ตามข้อ 17.1 ของ ui-design-system ทุกหน้าอยู่ใน AppShell กลาง และแยกให้เห็นว่าส่วนไหนเป็น "เวทีเกม" ที่ขอยกเว้นกฎสี (D1) ส่วนไหนใช้ component กลางเต็มร้อย รายการหน้าจอทั้งหมด flow และสิทธิ์ของแต่ละ role อยู่ในเอกสาร G0 (docs/ui-g0-scoping.md)

  • ขนาดอ้างอิง desktop 1280 px · มือถือ 360 px
  • ขั้นนี้ไม่ลงสี สีจริงมาจาก token ของ template ใน G2
  • ข้อความตัวอย่าง ตัวละคร "alice" จอมเวทเลเวล 5
ลายขวาง = เวทีเกมภาพ pixel art · canvas · บล็อกโค้ด ส่วนที่ขอยกเว้นใน D1
เส้นประ = ของจาก templateโลโก้และ AppShell มาจาก csmju-subsystem-web ห้ามวาดเอง
กรอบทึบ = component กลางการ์ด ปุ่ม ตาราง ฟอร์ม ใช้ token และ class ใน ui.ts

  4. บล็อกที่ยังล็อก ซ่อนจาก palette แต่บอกเป็นข้อความว่าจะปลดเมื่อไร (ผู้เล่นมีสิทธิ์แต่ยังไม่ถึง — ตามหลัก disable + เหตุผล)

  1. ฉากรบคือเวทีเกมชิ้นใหญ่ที่สุด อยู่ในการ์ด ไม่เต็มจอ ไม่ทับ AppShell · อัตราส่วนคงที่ (16:9 desktop · 4:3 มือถือ) จองพื้นที่ไว้ก่อนโหลดเพื่อกัน CLS · โหลดแบบ lazy เฉพาะหน้านี้
  2. ปุ่มควบคุมเป็นปุ่มกลาง ใช้คีย์บอร์ดได้ (Space หยุด/เล่น · → ข้าม) · ถ้าผู้ใช้ตั้งลดการเคลื่อนไหว ฉากเล่นทีละเทิร์นแบบภาพนิ่ง
  3. ไฮไลต์บรรทัดที่ตัดสินใจเทิร์นนี้ คือหัวใจของเกมสอนเขียนโปรแกรม ใช้กรอบ ไม่ใช้สีอย่างเดียว
  4. บันทึกการรบแบบข้อความ คู่กับฉากทุกเหตุการณ์ อ่านด้วย screen reader ได้ (aria-live) · บนมือถือสลับกับโค้ดด้วยแท็บ
  5. ผลการรบใช้การ์ดและ badge กลาง · "ดูโค้ดของคู่ดวล" แสดงเมื่อมีการดวล · ถ้ารอบนี้หมดอายุหรือรบไปแล้ว (409) กลับหน้าที่มาพร้อมข้อความจาก backend
