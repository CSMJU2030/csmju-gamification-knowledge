# บันทึกคำสั่งและการตีความ — Code Tower
> รวมทุกคำสั่งที่คุณให้ไว้ พร้อมสิ่งที่ผมตีความออกมาเป็นสเปกจริง
> จัดทำโดย Claude (PM) | 10 ก.ย. 2026 | ครอบคลุมตั้งแต่เริ่มโปรเจกต์ถึงจบรอบ 2B-1

## 1 · ตั้งบทบาท

> **คุณสั่ง:** "ผมอยากให้นายสมบทเป็น project management และ สร้าง subagent ช่วยงานนายตามเหตุสมควร"

**ผมตีความเป็น:** ไม่ใช่ "เขียนโค้ดให้หน่อย" แต่เป็น "รับผิดชอบผลลัพธ์ทั้งโปรเจกต์" — แปลว่าผมต้องแตกงานเอง วางสัญญาให้ทีมทำงานคู่ขนานได้ ตรวจรับก่อนส่ง และรายงานความคืบหน้าเป็นระยะ ส่วน subagent คือทีมงานที่ผมสั่งและตรวจ ไม่ใช่ตัวแทนที่ผมโยนงานให้แล้วจบ

**สิ่งที่ทำ:** ถามกลับก่อน 2 ข้อ (ประเภทงาน / สไตล์การทำงาน) แล้วตั้งทีม 5 บทบาท: `engine-dev` `backend-dev` `ui-dev` `pixel-artist` `qa`

---

## 2 · เลือกสไตล์การทำงาน

> **คุณเลือก:** ประเภทงาน = พัฒนาซอฟต์แวร์/ระบบ · สไตล์ = "วางแผนก่อนแล้วรอผมอนุมัติ"

**ผมตีความเป็น:** ห้ามลงมือก่อนอนุมัติในเรื่องที่กำหนดทิศทาง (สถาปัตยกรรม ดีไซน์ ขอบเขต) แต่ไม่ต้องถามซ้ำในเรื่องที่อนุมัติไปแล้ว — และทุกครั้งที่เสนอต้องมีข้อมูลพอให้ตัดสินใจได้จริง ไม่ใช่ถามลอย ๆ

**กลายเป็นจังหวะการทำงานตลอดโปรเจกต์:** เสนอแผน → คุณอนุมัติ → กระจายงาน → ผมตรวจรับ → ส่งมอบ

## 3 · ไอเดียเกม (คำสั่งที่ใหญ่ที่สุด)

> **คุณสั่ง:** "ไอเดียคร่าวๆ เป็น คลายๆ gamification บน web
> ระบบ 1.จะมี raid ไว้ฟาร์มอุปกรณ์ คิดคร่าวๆน่าจะมีสาย normal attack, magic, protect
> 2. ด่านจะเป็น แบบคล้ายๆหอคอยแต่ละชั้นจะมีทั้งหมด 10 wave เมื่อตีมอนตายจะดรอปของต่างๆ
> 3.แต่ละอุปกรณ์จะมีออฟต่างกับจำนวนช่องออฟ
> 4.มีระบบ status, level, อัพอุปกรณ์
> game play 1. จะเป็นแบบ auto สลับกันตี ซึ่งตัวละครเราจะ เซ็ต code ไว้ มอสเตอร์ก็มี code ของมันเอง
> 2. สามารถลงหอกับเพื่อนได้ ซึ่งถ้าลงกับเพื่อน monster จะเก่งเพิ่มขี้น 50% ตามจำนวนเพื่อนที่ลง
> ที่เหลือลองคิดไอเดียว่าต้องเพิ่มเติมอะไร อะไรดีไม่ดีทำได้ไม่ได้ ลองเสนอมา"

**ผมตีความเป็น:**

| สิ่งที่คุณพูด | ผมแปลงเป็นสเปก |
|---|---|
| 3 สาย (normal/magic/protect) | 3 อาชีพ: นักรบ / จอมเวท / ผู้พิทักษ์ + สเตตัส 5 ตัว (STR/INT/VIT/AGI/LUK) ที่ผูกกับสายพอดี |
| หอคอย ชั้นละ 10 wave | สร้างด่านด้วยสูตร + ตารางข้อมูล ไม่ออกแบบทีละด่าน · wave 10 = บอส |
| ออฟต่างกัน + จำนวนช่องต่างกัน | ผูก "จำนวนช่องออฟ" เข้ากับ **rarity 5 ระดับ** ให้ผู้เล่นเดาค่าได้จากสีเดียว |
| "เซ็ต code ไว้" | **จุดขายหลักของเกม** — ยกระดับจากฟีเจอร์หนึ่งเป็นแกนกลางทั้งโปรเจกต์ |
| ลงหอกับเพื่อน มอน +50% | คำนวณฝั่งเซิร์ฟเวอร์ทีเดียวแล้วส่งผลให้ทุกคนดู → ไม่ต้อง sync real-time และกันโกงในตัว |
| "ลองเสนอมา" | ผมเสนอเพิ่มเอง: บอสท้าย wave, ระบบย่อยของ, ตีบวก +15, **ดรอป +25%/เพื่อน** (เพราะมอนแกร่งขึ้นแล้วต้องคุ้ม) และบอกสิ่งที่ **ไม่ควรทำ**: PvP, ระบบ Energy, กราฟิก 3D |

**ข้อค้นพบที่เปลี่ยนสถาปัตยกรรม:** เพราะเป็น auto-battle ทั้งหมด การต่อสู้จึงเป็น "การคำนวณครั้งเดียว" ไม่ใช่เกม action → ทำให้ deterministic ได้ → ได้ replay, แชร์ build และทดสอบ balance อัตโนมัติมาฟรี ๆ

## 4 · อนุมัติสเปก MVP

> **คุณเลือก:** TypeScript ทั้งโปรเจกต์ · Rule List แบบ Gambit · UI + combat log ก่อน · เริ่มเลย

**ผมตีความเป็น:** ได้ไฟเขียวเต็มรูปแบบ ไม่ต้องถามซ้ำระหว่างทาง → ล็อกสัญญา (`types.ts` + `gamedata.json` + `api-spec.md`) แล้วปล่อย 3 ทีมทำงานพร้อมกัน

**ผลลัพธ์:** เกมเล่นครบ loop — สมัคร → ไต่หอ → ดรอปของ → แต่งตัว → อัพเลเวล

## 5–6 · แจ้งบั๊กตอนติดตั้ง (2 ครั้ง)

> **คุณส่ง:** log ของ `npm install` ที่ล้มเหลว — `prebuild-install`, `node-gyp`, "You need to install the latest version of Visual Studio"

**ผมตีความเป็น:** ไม่ใช่ "สอนวิธีลง Visual Studio" แต่คือ "ทำให้มันรันบนเครื่องผมได้โดยไม่ต้องลงอะไรเพิ่ม"

**วินิจฉัย:** Node 24 บนเครื่องคุณใหม่เกินกว่าที่ better-sqlite3 v11 มีไบนารีสำเร็จรูป มันเลยพยายามคอมไพล์เอง → อัพเป็น **v12.11.1**

**บทเรียนจากครั้งที่ 2:** คุณส่ง error เดิมกลับมา เพราะรอบแรกผม **ส่งไฟล์ไม่ครบ** — ผมไล่เลือกไฟล์ด้วยมือแทนที่จะเทียบทั้งโปรเจกต์ ตั้งแต่นั้นผมเปลี่ยนเป็นซิงก์ทั้งชุดแล้วเทียบ SHA-256 ทีละไฟล์ทุกครั้ง

## 7 · เปลี่ยนทิศทางครั้งใหญ่ (เฟส 2)

> **คุณสั่ง:** "ช่วยปรับ ตอนต่อสู้เป็น 2D มุมกล้องด้านหลัง คล้ายๆโปรเกม่อนหรือนายลองออกแบบมา ตั้งค่าการโจมตี ให้เป็นแบบ bloxcode แล้วแต่ละ bloxcode มี animation ต่างกัน รวมถึงความสามารถ การดรอป bloxcode ก็ดรอปจากม่อนในด่าน ลองคิดคร่าวๆดู"

**ผมตีความเป็น 3 งานที่แยกกันได้:**
1. ฉากต่อสู้ 2D มุมกล้องด้านหลัง (งานกราฟิก)
2. เปลี่ยน dropdown เป็นบล็อกที่มีแอนิเมชันและความสามารถเฉพาะตัว (งาน UI + engine)
3. บล็อกดรอปจากมอน (งานระบบเกม)

**ไอเดียที่ผมต่อยอดเอง:** รวมสองระบบเข้าด้วยกัน — **"มอนดรอปฟังก์ชันให้คุณเรียกใช้"** ของดรอปกลายเป็น API ที่ปลดล็อก ทำให้ลูปฟาร์มมีสองชั้น (ตัวเลข + ความสามารถใหม่) และเสนอ **ระบบ Memory (MB)** มาคุมไม่ให้ใส่ของแรงได้หมด

## 10 · คำถามที่เปลี่ยนคุณภาพของโปรเจกต์

> **คุณถาม:** "Python ชุดจำกัดที่เราแปลเอง ไม่ใช่ Python จริง คืออะไร แล้วมีวิธีแนะนำไหมผม อยากให้ผู้เล่นสามารถเรียนรู้ได้"

**ผมตีความเป็น:** คุณไม่ได้ถามนิยามอย่างเดียว แต่กำลังบอกว่า **"การเรียนรู้ของผู้เล่นคือเป้าหมายจริงของเกมนี้"** → ต้องออกแบบใหม่โดยยึดเป้านี้เป็นหลัก

**สิ่งที่เปลี่ยนเพราะคำถามนี้:**
- **Differential test เทียบ CPython จริง** — เปลี่ยนคำว่า "เหมือน Python" จากคำโฆษณาเป็นสิ่งที่พิสูจน์ได้ในทุก CI run
- **ภาษาเป็นของดรอป** — ปลดล็อกไวยากรณ์ทีละอย่างตามชั้น กลายเป็นหลักสูตรที่ซ่อนอยู่ในเกม
- ดูโค้ดมอนสเตอร์ได้ · error เลียนแบบ Python จริงแต่อธิบายไทย · ดาวน์โหลดเป็นไฟล์ `.py`

## 11–12 · อนุมัติแนวทาง แล้วแจ้ง build error

> **คุณเลือก:** Python ชุดจำกัด + ทดสอบเทียบ CPython · เอาหลักสูตรซ่อนในเกม · เอาฟีเจอร์เรียนรู้ทั้ง 4 อย่าง
> **แล้วส่ง:** TS error 2 ตัว (`animation` ไม่มีใน SkillDef, `import.meta.glob` ไม่รู้จัก)

**ผมตีความเป็น:** อาการเดิมของโรคเดิม — ส่งไฟล์ไม่ครบอีกครั้ง (`client/src/types.ts` และ `vite-env.d.ts` ตกหล่น) เป็นเคสคลาสสิกที่ build ผ่านฝั่งผมแต่พังฝั่งคุณ → แก้แล้วยืนยันด้วยการเทียบ hash ทั้ง 58 ไฟล์

## 13–14 · สั่งงานรอบถัดไป

> **คุณสั่ง:** "ขอเสนอเพิ่มขั้นต่อไป bloxcode ขอเป็นภาษา eng อยากให้ลากไปวางแทน ปรับ main ui ด้วย"
> **แล้วเลือก:** BloxCode อังกฤษ ที่เหลือไทย · ยกเครื่องหน้าตาใหม่ทั้งหมด · เน้นมือถือด้วย

**ผมตีความเป็น 3 งาน และเห็นกับดักหนึ่งอัน:**
- ภาษา → วางกติกาชัด: **ทุกอย่างในโซนโค้ดเป็นอังกฤษ นอกโซนโค้ดเป็นไทย** (เพราะ `if`/`elif` แปลไม่ได้อยู่แล้ว ถ้าป้ายเป็นไทยผู้เล่นต้องแปลกลับไปมาในหัว)
- ลากวาง + มือถือ → **กับดัก:** HTML5 Drag and Drop API ใช้ไม่ได้บนมือถือเลย ซึ่งขัดกับข้อที่คุณเพิ่งสั่ง → ใช้ Pointer Events แทน และเพิ่ม "แตะเลือก → แตะวาง" เป็นทางหลักบนจอเล็ก
- ยกเครื่อง UI → **จุดที่ผมตัดสินใจต่างจากที่คุณอาจคาด:** ใช้พิกเซลกับกรอบ/ภาพ แต่ **ไม่ใช้ฟอนต์พิกเซล** เพราะฟอนต์พิกเซลไทยทำให้สระซ้อนจนอ่านไม่ออก

## 15–16 · ปล่อยให้เดินเอง

> **คุณสั่ง:** "started" แล้วต่อมา "ทำขั้นต่อไป"

**ผมตีความเป็น:** ไม่ต้องถามอะไรอีก เดินตามแผนที่อนุมัติไว้ — และเมื่อเจอทางแยกให้ **ตัดสินใจเองแล้วรายงานเหตุผล** ไม่ใช่หยุดรอ

**สิ่งที่ผมตัดสินใจเองในช่วงนี้ (และรายงานไว้):**
- `me.def` ใช้ไม่ได้ (เป็นคำสงวน Python) → เปลี่ยนเป็น `me.defense` — **สเปกผมเองผิด**
- สูตร Memory เดิมไม่เคยบีบใครเลย → แก้จาก `10+level/2` เป็น `6+level/3`
- เลื่อนการทำ AI มอนสเตอร์ให้ต่างกันไปรอบ 2C เพื่อไม่ต้องจูน balance สองรอบ

## 17–19 · ขอสรุป

> "ทำอะไรไปแล้วบ้างนะ" → "สรุปมาย่อๆความคืบหน้า" → "ขอเป็น prompt ที่ผมสั่งทั้งหมดและเป็นรูปแบบที่นายตีความออกมา"

**ผมตีความเป็น:** อยากได้ภาพรวมที่กระชับลงเรื่อย ๆ และสุดท้ายคือ **อยากเห็นว่าคำพูดสั้น ๆ ของคุณกลายเป็นสเปกได้อย่างไร** — เอกสารฉบับนี้คือคำตอบนั้น

## รูปแบบการทำงานที่ตกผลึกจากโปรเจกต์นี้

1. **คุณพูดเป็นไอเดีย ผมแปลงเป็นสเปกที่ทดสอบได้** — "ออฟต่างกัน" → rarity 5 ระดับผูกกับจำนวนช่อง · "เซ็ต code" → ภาษา Python พร้อม differential test
2. **ล็อกสัญญาก่อนกระจายงาน** — `types.ts`, `spec.ts`, `tokens.css`, `api-spec.md` คือเหตุผลที่ 3 ทีมทำงานพร้อมกันได้โดยไม่ชนกัน
3. **ผมไม่เชื่อรายงานของทีมโดยไม่ตรวจเอง** — เจอ 4 เรื่องจากการตรวจเอง: สไปรต์ขาด 7 ตัว, ฉากไม่เต็มจอ, differential test จับ mutation ไม่ได้จริง, ปุ่ม "ถอด" กดไม่ได้
4. **สิ่งที่คุณเห็นต้องมาจากของจริง** — ภาพ mockup ทุกใบเรนเดอร์จาก pipeline จริง ภาพหน้าจอทุกใบมาจากเซิร์ฟเวอร์ที่รันอยู่
5. **ส่งไฟล์ = ซิงก์ทั้งโปรเจกต์แล้วเทียบ hash** — บทเรียนราคาแพงจากรอบที่ 5 และ 12
