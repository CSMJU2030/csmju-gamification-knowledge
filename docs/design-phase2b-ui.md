## 2. ภาษา: ทำไม BloxCode เป็นอังกฤษถึงถูกต้อง

โค้ดที่ผู้เล่นเขียนเป็น Python อยู่แล้ว — `if` `elif` `else` `and` `or` เป็นคำสงวนของภาษา แปลไม่ได้
ถ้าป้ายบล็อกเป็นไทยแต่โค้ดเป็นอังกฤษ ผู้เล่นต้องแปลกลับไปมาในหัวตลอดเวลา และสิ่งที่เรียนจะ**ไม่ตรง**กับ Python จริง

**กติกาแบ่งภาษาให้ชัด:**

| เป็นอังกฤษเสมอ | เป็นไทยเสมอ |
|---|---|
| บล็อกทุกชนิด, ชื่อฟังก์ชัน/ตัวแปร, มุมมอง Python, หัวข้อ palette (CONTROL / ACTIONS / TARGETS), ชื่อสกิลในโค้ด (`cast("firebolt")`) | เมนู, หน้าตัวละคร, กระเป๋า, หอคอย, บันทึกการต่อสู้, ชื่อมอนสเตอร์, ชื่อไอเทม, คำอธิบาย/คำแนะนำ, ข้อความ error (อธิบายเป็นไทย แต่**ชื่อ error เป็นอังกฤษ** เช่น `IndentationError` — เพราะเจอแบบนี้ใน Python จริง) |

ตัวอย่างข้อความ error:
```
IndentationError — บรรทัด 5
    การเยื้องไม่ถูกต้อง: ต้องเยื้องเข้าไป 4 ช่องหลัง if
```

## 3. Drag & Drop ที่ทำงานได้ทั้งเมาส์และนิ้ว

**ห้ามใช้ HTML5 Drag and Drop API** — มันไม่ทำงานบนมือถือเลย ซึ่งขัดกับข้อ 3 ที่เราตัดสินใจไว้

**ใช้ Pointer Events แทน** (`pointerdown` / `pointermove` / `pointerup`) — โค้ดชุดเดียวรองรับเมาส์ นิ้ว และปากกา ทั้งหมด

รายละเอียดที่ต้องทำให้ถูก:
- `touch-action: none` บนบล็อกที่ลากได้ ไม่งั้นนิ้วจะเลื่อนหน้าจอแทนการลาก
- **ต้องขยับเกิน 6px ก่อนถึงนับว่าเป็นการลาก** — ไม่งั้นการ "แตะ" จะกลายเป็นลากโดยไม่ตั้งใจ
- ตัวบล็อกที่ลากอยู่เป็น layer ลอย (`position: fixed`) ตามนิ้ว/เมาส์ พร้อมเงาและเอียงเล็กน้อยให้รู้สึกว่า "ยกขึ้นมา"
- ช่องที่วางได้เรืองแสง + ขอบประ, ช่องที่วางไม่ได้ (เช่น MB ไม่พอ) เป็นสีแดงจาง
- เลื่อนจออัตโนมัติเมื่อลากไปใกล้ขอบบน/ล่าง
- ลากออกนอกโปรแกรม = ลบบล็อกนั้น (มีถังขยะโผล่มาให้เห็น)

**และต้องมีทางเลือกที่ไม่ต้องลากเสมอ** — บนจอเล็กการลากแม่นยำยาก:
> **แตะบล็อกเพื่อเลือก → แตะช่องที่ต้องการเพื่อวาง**

วิธีนี้เร็วกว่าการลากบนมือถือด้วยซ้ำ และช่วยคนที่ใช้เมาส์ไม่ถนัด/ใช้คีย์บอร์ด เราจะรองรับทั้งสองทางเสมอ

## 4. ระบบดีไซน์ใหม่ (Design System)

ปัญหาปัจจุบัน: ฉากต่อสู้เป็นพิกเซล 16-bit แต่หน้าอื่นเป็นเว็บแอปทั่วไป → ดูเหมือนคนละเกม

**ทิศทาง: "เกมพิกเซล แต่ตัวหนังสืออ่านง่าย"**
ใช้กรอบ/ปุ่ม/ไอคอนสไตล์พิกเซล (ขอบหนา 2px, เงาแข็งด้านล่าง, ไม่มีมุมโค้งฟุ้ง ๆ) แต่ **ตัวอักษรยังเป็นฟอนต์ระบบ** ไม่ใช้ฟอนต์พิกเซล

> **เหตุผลสำคัญ:** ฟอนต์พิกเซลภาษาไทยแทบไม่มีที่ใช้งานได้จริง สระบน-ล่างจะซ้อนกันจนอ่านไม่ออก
> ความสวยแบบเรโทรไม่คุ้มกับการที่ผู้เล่นอ่านไม่รู้เรื่อง — เราจึงใช้พิกเซลกับ *กรอบและภาพ* ไม่ใช่ *ตัวอักษร*

**สิ่งที่ทำให้ UI ผูกกับเกม:** ใช้สไปรต์จริงจาก `sprites.json` มาเป็นรูปตัวละครในหน้าอุปกรณ์และรูปโปรไฟล์บนแถบบน — ไม่ต้องวาดเพิ่ม ใช้ renderer ตัวเดียวกับฉากต่อสู้

### โทเคนสี
```
--bg      #0b0e18   พื้นหลังนอกสุด
--panel   #141a2c   พื้นแผง
--line    #2a3352   เส้นขอบ
--ink     #0a0d16   ขอบเข้ม/เงาแข็ง
--gold    #d8b95c   สีหลัก (เน้น, ปุ่มยืนยัน)
--code    #8ff0c0   สีประจำ BloxCode (เขียวมิ้นต์ = แยกโซนโค้ดออกจากเกม)
```

### เลย์เอาต์ตามขนาดจอ
| ขนาด | เมนู | เนื้อหา |
|---|---|---|
| ≥1024px | sidebar ซ้าย | 2 คอลัมน์ |
| 640–1023px | sidebar ยุบเป็นไอคอน | 1 คอลัมน์ |
| <640px (มือถือ) | **แถบแท็บล่าง** (นิ้วโป้งเอื้อมถึง) | 1 คอลัมน์ · palette ของ BloxCode เป็นลิ้นชักด้านล่าง |

ฉากต่อสู้บนมือถือ: หมุนเป็นแนวนอนอัตโนมัติ หรือย่อ canvas ให้พอดีความกว้าง (canvas เป็น 256×160 อยู่แล้ว ย่อได้ไม่เสียคุณภาพ)

## 5. แผนงานก้อน 2B (แบ่งเป็น 3 รอบส่ง)

| รอบ | เนื้อหา | ทีม | ได้เห็นอะไร |
|---|---|---|---|
| **2B-0** | ระบบดีไซน์ใหม่ + ยกเครื่องทุกหน้าเดิม (ตัวละคร/กระเป๋า/หอคอย/ล็อกอิน) + responsive + แถบแท็บล่างบนมือถือ | `ui-dev` | เกมหน้าตาใหม่ทั้งหมด เล่นบนมือถือได้ |
| **2B-1** | ตัวภาษา: tokenizer/parser/evaluator + differential test เทียบ CPython + แปลง AST ⟷ บล็อก ⟷ Python + API บันทึก/ตรวจ + MB + ปลดล็อกไวยากรณ์ตามชั้น | `engine-dev` + `backend-dev` | โค้ดสั่งตัวละครได้จริง |
| **2B-2** | เอดิเตอร์: บล็อกลากวาง (pointer events) + แตะเลือก-แตะวาง + มุมมอง Python + error ไทย + ไฮไลต์บรรทัดตอนสู้ + migration กฎเดิม | `ui-dev` | BloxCode ใช้งานได้เต็มรูปแบบ |

ฟีเจอร์เรียนรู้ที่เหลือ (ห้องซ้อม, ด่านปริศนา, ดูโค้ดมอน, ดาวน์โหลด `.py`) อยู่ในก้อน **2B-3** ตามที่ตกลงไว้

## 6. ความเสี่ยงที่ประเมินไว้

| ความเสี่ยง | วิธีรับมือ |
|---|---|
| ยกเครื่อง UI แล้วของเดิมพัง (สวมของ/อัพแต้ม/ตีหอ) | ไม่แตะ API และ logic เดิมเลย เปลี่ยนเฉพาะชั้นการแสดงผล + ทดสอบ end-to-end ทุกหน้าก่อนส่ง |
| ลากวางบนมือถือใช้ยาก | มี "แตะเลือก → แตะวาง" เป็นทางหลักบนจอเล็ก การลากเป็นทางเลือก |
| จอเล็กมากแสดงโปรแกรมยาว ๆ ไม่ไหว | ย่อการเยื้อง, ซ่อนเลขบรรทัดใต้ 400px, พับบล็อกลูกได้ |
| ผู้เล่นเดิมมีกฎแบบเก่า | migration อัตโนมัติในรอบ 2B-1 พร้อมทดสอบกับข้อมูลจริงก่อนปล่อย |
| งานรวมสามรอบใหญ่กว่าที่ประเมิน | ส่งทีละรอบ ให้คุณลองเล่นและปรับทิศได้ระหว่างทาง |
