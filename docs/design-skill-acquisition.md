# วิธีได้สกิลใหม่ — ข้อเสนอให้เลือกทาง

สถานะ: **เลือกทางแล้ว 8 ต.ค. 2569 — ทำทุกทางที่เสนอ (A · B · F · D) ทีละระยะ · สกิลภูมิภาคแยกตามอาชีพ** (ดูข้อ 7) · ระยะ S1 ฝั่ง engine + backend ทำแล้ว (ข้อ 5) · ต่อจากความเห็นผู้ใช้ "วิธีได้สกิลใหม่ ลองไปคิดมา"
อ้างอิง: [`design-phase2-bloxcode.md`](design-phase2-bloxcode.md) §3 (ไอเดียเดิม: สกิล = บล็อกที่ดรอปจากมอน)

## 1. ตอนนี้เป็นยังไง

- สกิลมี **9 ตัว อาชีพละ 3** ได้ตามเลเวลอย่างเดียว (`unlockedSkills(classId, level)`) และตัวสุดท้ายได้ที่ **เลเวล 10**
  - นักรบ: ฟันสายฟ้าแลบ Lv1 · ดาบหมุนวน Lv5 · ปิดฉาก Lv10
  - จอมเวท: ลูกไฟ Lv1 · พายุน้ำแข็ง Lv4 · ฟื้นฟู Lv7
  - ผู้พิทักษ์: โล่กระแทก Lv1 · ยั่วยุ Lv3 · ปราการ Lv6
- เลเวลไม่มีเพดาน หลังเลเวล 10 **ไม่มีสกิลใหม่อีกเลย**
- การได้สกิล **ไม่เกี่ยวกับการเขียนโค้ด** ฟาร์มจนเลเวลถึงก็ได้เหมือนกันหมด
- ของที่มีอยู่แล้วและใช้ต่อได้:
  - **ไวยากรณ์ปลดตามชั้นหอคอย:** `if` ชั้น 1 · `elif` 3 · `and/or` 4 · เลขคณิต 5 · ตัวแปร 6 · `for` 8
  - **ภูมิภาค 5 แห่ง** แต่ละแห่งมี "บทเรียน" (`lessonTh`) และกลไกที่บังคับให้ใช้แนวคิดโค้ดหนึ่งอย่าง:

| ภูมิภาค | กลไก | แนวคิดที่ต้องใช้ |
|---|---|---|
| ป่าเริ่มต้น | หมาป่าง้างหมายหัว แล้วเทิร์นถัดไปกัดเกือบครึ่งหลอด | `has_debuff("marked")` → `defend()` เฉพาะเทิร์นนั้น |
| หมู่เกาะ | มอนเร็วกว่า ได้ลงมือก่อนเสมอ | เผื่อเลือดไว้ก่อน (เงื่อนไข `me.hp_pct` ที่สูงพอ) |
| ซากปรักหักพัง | เมจมืดหมัดเบาแต่เวทหนัก | เลือกเป้า `weakest(enemies)` ไม่ใช่ `deadliest` |
| ดินแดนน้ำแข็ง | โกเลมง้างทุก 3 เทิร์น ทุบหลายเท่า | ตั้งการ์ดเฉพาะเทิร์นที่ถูกหมายหัว |
| ภูเขาไฟ | ยักษ์หินตีแรงกว่าทั้งเวฟรวมกัน | `deadliest(enemies)` ต้องตายก่อน |

## 2. หลักที่ใช้เลือก

1. **ได้สกิลเพราะเขียนโค้ดเป็น** ไม่ใช่เพราะเล่นนานหรือดวงดี (เกมนี้คือเครื่องมือสอน)
2. **ดวงไม่เป็นตัวตัดสิน** ตามกติกาเดิมของมอน EX ใน gamedata
3. **ตรวจที่เซิร์ฟเวอร์จากผลการรบ** ไม่เชื่อสิ่งที่หน้าเว็บส่งมา · ผลเดิมเมื่อ seed เดิม
4. **ไม่ตัดของเดิม** สกิล 9 ตัวตามเลเวลยังได้เหมือนเดิม คนที่ยังไม่ได้สกิลใหม่ก็เล่นต่อได้
5. **ทำทีละก้อนได้** ไม่ต้องรื้อระบบใหญ่

## 3. ทางเลือก

| | วิธี | สอนโค้ดได้แค่ไหน | งานที่ต้องทำ | ความเสี่ยง |
|---|---|---|---|---|
| **A** | **สกิลประจำภูมิภาค:** ชนะรอบลึกสุดของภูมิภาค **โดยทำตามบทเรียนของภูมิภาคนั้นได้จริง** (เช่น ถูกหมายหัวแล้วตั้งการ์ดทันทีทุกครั้ง) → ได้สกิลของภูมิภาคนั้น | **สูงสุด**: สกิลคือรางวัลของแนวคิดที่ภูมิภาคสอนอยู่แล้ว | ตัวตรวจ "พิสูจน์" 5 ตัวใน engine (อ่านจากเหตุการณ์การรบ) · ข้อมูลสกิลใหม่ · ตารางเก็บผลพิสูจน์ · หน้าเว็บบอกเงื่อนไข | เงื่อนไขต้องวัด "พฤติกรรม" ไม่ใช่ "ผล" ไม่งั้นของแรงแทนโค้ดได้ |
| **B** | **สกิลจากความชำนาญ:** งานสะสมของ STR/INT/VIT (ระบบความชำนาญที่มีแล้ว) ถึงเกณฑ์ → ได้สกิลสายนั้น | กลาง: สะท้อนสไตล์ที่โปรแกรมเล่น แต่ฟาร์มได้ | น้อย: ต่อจาก `proficiencyFromBattle` | กลายเป็นฟาร์มตัวเลขอีกแบบ |
| **C** | **รางวัลจากโจทย์ของอาจารย์:** อาจารย์ผูกสกิลเป็นรางวัลของโจทย์ (ต่อจากมอนของโจทย์) | สูง ถ้าอาจารย์ตั้งโจทย์ดี | ช่องรางวัลในโจทย์ · ตรวจว่าชนะจริง | ไม่ยุติธรรมข้ามกลุ่มเรียน (สกิลได้เฉพาะคนที่อาจารย์คนนั้นสอน) |
| **D** | **ดรอปจากมอน/บอส** (ไอเดียเดิมเฟส 2) + งบ Memory | ต่ำ: ได้เพราะดวง | มาก: ตารางดรอป · บล็อกซ้ำ · ย่อย/คราฟต์ · งบ MB | ขัดหลักข้อ 2 · ระบบใหญ่ |
| **E** | **ครูฝึกในเมือง:** ซื้อสกิลด้วยทอง/วัสดุ | ไม่มี | น้อย | ได้สกิลโดยไม่ต้องเขียนอะไร |
| **F** | **ความเชี่ยวชาญสกิล:** ใช้สกิลเดิมสำเร็จตามเงื่อนไขครบ N ครั้ง (เช่น ปิดฉากใส่เป้าเลือดต่ำกว่า 30%) → สกิลขั้น 2 | สูง: บังคับใช้ `if` กับสกิลให้ถูกจังหวะ | กลาง: ตัวนับต่อสกิล · ข้อมูลขั้นสกิล | ต้องจูนตัวเลขเพิ่มทุกขั้น |

## 4. ข้อเสนอ

**ทำ A เป็นหลัก** แล้วต่อด้วย F ภายหลัง · **ไม่ทำ D และ E** · C ใช้เครื่องตรวจตัวเดียวกับ A ได้ แต่ให้รางวัลเป็นตราผ่านหรือ EXP แทนสกิล (เลี่ยงเรื่องความยุติธรรมข้ามกลุ่มเรียน)

เหตุผล: ภูมิภาคสอนแนวคิดอยู่แล้วแต่ตอนนี้ไม่มีรางวัลที่ผูกกับบทเรียน ผ่านแบบ "ตีแรงจนชนะ" ก็ได้ของเท่ากับคนที่ทำตามบทเรียน ·
A ปิดช่องนี้และให้เหตุผลที่จะกลับไปแก้โค้ด · สกิลใหม่ใช้ประเภทที่ engine มีแล้ว (กายภาพ · เวท · ฮีล · โล่ · ยั่วยุ) และแอนิเมชัน 12 แบบที่มีอยู่ จึงเป็นงานข้อมูล ไม่ต้องเพิ่มระบบสถานะใหม่

## 5. A แบบละเอียด

### 5.1 เงื่อนไขพิสูจน์ (ทำแล้ว · `packages/engine/src/proofs.ts`)

ทุกข้อ: **ชนะรอบลึกสุดของภูมิภาค** และทำตามบทเรียนครบในการรบครั้งเดียวกัน · ตรวจจากบันทึกการรบที่เซิร์ฟเวอร์จำลองเอง

| ภูมิภาค | ต้องเห็นในการรบ | ข้อกันโกง |
|---|---|---|
| ป่าเริ่มต้น | ถูกหมาป่าหมายหัวอย่างน้อย 3 ครั้ง และ **ทุกครั้ง** เทิร์นถัดไปของคุณเป็นตั้งการ์ด/โล่/ยั่วยุ | ตั้งรับตอนไม่ถูกหมายหัวไม่เกิน 25% ของเทิร์นเหล่านั้น · ล้มตัวที่หมายได้ก่อนไม่นับว่ารับทัน |
| หมู่เกาะ | ดูแลเลือด (ฮีล/โล่/ตั้งการ์ด) อย่างน้อย 2 ครั้ง และเลือดไม่ต่ำกว่า 50% ตลอดการรบ | ตั้งรับไม่เกิน 40% ของเทิร์น · ไม่ดูแลเลือดเลยไม่ผ่านแม้เลือดเต็มเพราะของแรง |
| ซากปรักหักพัง | เมจมืดตายเป็นตัวแรกของเวฟ อย่างน้อย 4 เวฟ และ 80% ของเวฟที่มีมันปน | นับเฉพาะเวฟที่มีมอนมากกว่า 1 ตัว |
| ดินแดนน้ำแข็ง | ถูกโกเลมหมายหัวอย่างน้อย 3 ครั้ง ตั้งรับทันทุกครั้ง | เหมือนป่าเริ่มต้น |
| ภูเขาไฟ | ยักษ์หินตายเป็นตัวแรก อย่างน้อย 4 เวฟ และ 80% ของเวฟที่มีมันปน | เหมือนซากปรักหักพัง |

- วัด **พฤติกรรม** ไม่วัดว่าโค้ดเขียนว่าอะไร: ต่อบล็อกหรือพิมพ์ Python ผ่านเหมือนกัน
- ทุกรอบตรวจให้ดูว่าขาดข้อไหน แต่นับเฉพาะรอบลึกสุดที่ชนะ (`eligible` · `passed`)
- หมู่เกาะเปลี่ยนจากร่าง ("ดูแลเลือดตอนยังเกิน 50%" · "เลือดไม่ต่ำกว่า 25%"): วัดแล้วโปรแกรมตามบทเรียนก็ไม่ผ่านเพราะเลือดแทบไม่ลงถึงช่วงนั้น
  เกณฑ์ใหม่ทำให้ "ตั้งเงื่อนไขเลือดต่ำเกินไป" ตก และ "ตั้งไว้สูงพอ" ผ่าน ตรงกับบทเรียนของภูมิภาค

**ผลวัดด้วย `node packages/engine/tools/proofprobe.cjs`** (รอบลึกสุด · 20 seed ต่อจุด · ไม่ใส่ของ · มีสกิลของภูมิภาคก่อนหน้าแล้ว)

| ภูมิภาค | โปรแกรมตามบทเรียน: ผ่าน/ชนะ | โปรแกรมอื่น: ผ่าน (ชนะ) |
|---|---|---|
| ป่าเริ่มต้น | นักรบ 11/11 · 16/20 · จอมเวท 16/17 · 19/20 · ผู้พิทักษ์ 16/16 · 20/20 | ตีอย่างเดียว 0 (ชนะสูงสุด 19/20) · ตั้งรับตอนเลือดน้อย 0 · ตั้งรับตลอด 0 |
| หมู่เกาะ | นักรบ 6/16 · 20/20 · จอมเวท 10/20 · 20/20 · ผู้พิทักษ์ 20/20 · 20/20 | ตีอย่างเดียว 0 (ชนะ 20/20) · เงื่อนไขเลือด 30% 0 (ชนะ 20/20) |
| ซากปรักหักพัง | ทุกอาชีพ 14/14 · 20/20 | เลือกตัวตีแรงก่อน 0 (ชนะถึง 20/20) |
| ดินแดนน้ำแข็ง | นักรบ 13/13 · 20/20 · จอมเวท 12/12 · 20/20 · ผู้พิทักษ์ 14/14 · 20/20 | ตีอย่างเดียว 0 (ชนะ 20/20) |
| ภูเขาไฟ | นักรบ 9/10 · 15/16 · จอมเวท 10/11 · 18/19 · ผู้พิทักษ์ 10/11 · 15/16 | ตีตัวเลือดน้อยก่อน 0 (ชนะถึง 12/20) |

ตัวเลขคู่ = ที่เลเวลต่ำสุดที่ชนะได้ครึ่งหนึ่ง และเลเวลนั้น +4 · ที่ชนะแต่ไม่ผ่านทั้งที่ทำตามบทเรียน:
ป่าเริ่มต้น = ถูกหมายหัวไม่ถึง 3 ครั้งเพราะตัวละครแรงจนหมาป่าตายก่อนง้าง · หมู่เกาะที่เลเวลต่ำสุด = เลือดลงต่ำกว่าครึ่ง ·
ภูเขาไฟ = เวฟที่ยักษ์หินปนมีไม่ถึง 4 เวฟ — ทั้งหมดเข้ารอบใหม่แล้วลองอีกได้

### 5.2 สกิลที่ได้ (ทำแล้ว · ตัวเลขรอบแรก)

ภูมิภาคละ 1 สกิล **แยกตามอาชีพ** (รวม 15 ตัว) · ใช้ชนิดและแอนิเมชันที่ตัวรบมีอยู่แล้ว (ไม่มีกลไกใหม่) · โล่และฮีลคิดเป็น % ของเลือดสูงสุด

| ภูมิภาค | นักรบ | จอมเวท | ผู้พิทักษ์ |
|---|---|---|---|
| ป่าเริ่มต้น | ตั้งหลัก `guard_up` โล่ 10% · MP 6 | ม่านมานา `mana_veil` โล่ 12% · MP 8 | การ์ดเหล็ก `iron_guard` โล่ 15% · MP 8 |
| หมู่เกาะ | ลมหายใจที่สอง `second_wind` ฮีล 15% · MP 10 | สมานแผล `mend` ฮีล 15% · MP 9 | ฮึดสู้ `rally` ฮีล 15% · MP 10 |
| ซากปรักหักพัง | แทงทะลวง `pierce` 200% ATK · MP 11 | ศรเวท `arcane_bolt` 185% MATK · MP 10 | โล่พุ่ง `shield_rush` 170% ATK · MP 10 |
| ดินแดนน้ำแข็ง | ยืนหยัด `brace` โล่ 20% · MP 12 | กำแพงน้ำแข็ง `ice_wall` โล่ 22% · MP 14 | ป้อมปราการ `bulwark` โล่ 30% · MP 18 |
| ภูเขาไฟ | ทุบเกราะ `sunder` 230% ATK · MP 16 | ดาวตก `meteor` 250% MATK · MP 20 | ค้อนทุบ `crushing_blow` 210% ATK · MP 15 |

ชื่อในวงเล็บคือชื่อที่เขียนใน `cast()` · ไม่ชนกับสกิลอื่น (เทสต์คุม)

### 5.3 สิ่งที่เปลี่ยนในระบบ (ทำแล้ว)

- **ข้อมูล:** `gamedata.skills` เพิ่ม 15 ตัว มีช่อง `region` (สกิลกลุ่มนี้ `unlockLevel` ไม่มีความหมาย)
- **engine:** `proofs.ts` — `regionProof(regionId, depth, result, heroId, heroMaxHp)` · `proofRequirements` · `skillsFor(classId, level, provedRegions)` · `regionSkillFor` ·
  ข้อความของตัวตรวจโปรแกรมบอกว่าสกิลภูมิภาค "ได้จากการพิสูจน์บทเรียนของ…" แทน "ปลดที่เลเวล"
- **ฐานข้อมูล:** คอลัมน์ `characters.proved_regions TEXT[]` (เปลี่ยนจากร่างที่เป็นตาราง `region_proofs`):
  ทุกที่ที่คิดสกิล (รบ · ตรวจโปรแกรม · หน้าตัวละคร · สแนปช็อตดวล) มีแถวตัวละครอยู่แล้ว จึงไม่ต้องถามฐานข้อมูลเพิ่ม ·
  เขียนในทรานแซกชันเดียวกับผลการรบบนแถวที่ล็อกไว้ ได้สกิลครั้งเดียวแม้รบพร้อมกัน · เก็บผลพิสูจน์ ไม่ได้เก็บสกิล
- **API:** `POST /battles` (ภูมิภาค) เพิ่ม `proof { regionId, eligible, passed, newlyProved, checks[], skill }` ·
  `GET /regions` เพิ่ม `proof { requirementsTh[], proved, skill }` (null = หอคอย · เมือง) ·
  `availableSkills` ของโปรแกรมและ `skills` ของตัวละครรวมสกิลภูมิภาคที่ได้แล้ว (มีช่อง `region`) · `GET /game-data` สกิลมีช่อง `region`
- **ผู้เล่นเดิม:** ต้องพิสูจน์ใหม่ (ประวัติการรบไม่เก็บเหตุการณ์ ย้อนตรวจไม่ได้) · สกิล 9 ตัวเดิมไม่หาย

### 5.4 แบ่งงาน

แบ่ง 2 PR เหมือนมอนของโจทย์:

1. **PR A:** engine + backend + API — ตัวตรวจ 5 ตัวพร้อมเทสต์ · ข้อมูลสกิล 15 ตัว · คอลัมน์ `proved_regions` · e2e (ทำแล้ว)
2. **PR B:** หน้าเว็บ — แผงภูมิภาค · แถบได้สกิล · หน้าโปรแกรม

F (สกิลขั้น 2) เป็นงานถัดไปหลังเห็นผลเล่นจริงของ A

## 6. คำถามที่ต้องตัดสินก่อนลงมือ

1. เลือกทาง **A** (แนะนำ) หรือทางอื่น
2. สกิลภูมิภาค **แยกตามอาชีพ 15 ตัว** (แนะนำ) หรือใช้ร่วมทุกอาชีพ 5 ตัว (งานน้อยกว่า แต่บางอาชีพจะได้สกิลที่ไม่เข้ากับสเตตัส)
3. ผู้เล่นเดิมต้องพิสูจน์ใหม่ — รับได้ไหม
4. C (โจทย์ของอาจารย์) ให้รางวัลเป็นตราผ่าน/EXP ไม่ให้สกิล — ตกลงไหม

## 7. ตัดสินใจ 8 ต.ค. 2569 และแผนทำทีละระยะ

PM เลือก **ทุกทางที่เสนอ (A · B · F · D)** และ **สกิลภูมิภาคแยกตามอาชีพ 15 ตัว** · C และ E ไม่อยู่ในตัวเลือก จึงยังไม่ทำ

ทำทีละระยะ เรียงจากสอนโค้ดได้มากและงานน้อย ไปหางานใหญ่ · จบแต่ละระยะวัดด้วย `probe` และลองเล่นก่อนเริ่มระยะถัดไป

| ระยะ | ทาง | สิ่งที่ได้ | งานหลัก |
|---|---|---|---|
| S1 | **A** สกิลภูมิภาค | 15 สกิล (5 ภูมิภาค × 3 อาชีพ) | ตัวตรวจพิสูจน์ 5 ตัว · คอลัมน์ `proved_regions` · API · หน้าเว็บ (ข้อ 5) |
| S2 | **F** สกิลขั้น 2 | สกิลเดิม 9 ตัวมีขั้น 2 | เงื่อนไข "ใช้ถูกจังหวะ" ต่อสกิล · ตัวนับ `skill_mastery` |
| S3 | **B** สกิลจากความชำนาญ | อาชีพละ 3 สกิล (สาย STR · INT · VIT) | เกณฑ์จากสเตตัสที่ความชำนาญแจก · ไม่ต้องมีตารางใหม่ |
| S4 | **D** ตำราสกิลจากบอส | สกิลแรร์ที่มีกลไกใหม่ (พิษ · มึน · บัฟ · หลายฮิต · ดูดเลือด) | ระบบสถานะใน engine · ดรอปจากบอสหอคอย 10 ตัวและมอน EX |

### 7.1 เงื่อนไขของแต่ละระยะ (ร่าง)

- **F — สกิลขั้น 2:** นับเฉพาะครั้งที่ใช้ถูกจังหวะ เช่น ปิดฉากใส่เป้าเลือดต่ำกว่า 30% · พายุน้ำแข็งโดนอย่างน้อย 3 ตัว ·
  ฟื้นฟูตอนเลือดต่ำกว่าครึ่ง · ยั่วยุตอนมีศัตรูอย่างน้อย 2 ตัว · ครบ N ครั้ง → แรงขึ้นหรือ MP ถูกลง (ไม่มีสกิลตัวใหม่)
- **B — สกิลจากความชำนาญ:** สเตตัสที่ความชำนาญแจกให้สายไหนถึงเกณฑ์ (เช่น VIT ถึง X) → ได้สกิลสายนั้นของอาชีพตัวเอง ·
  ผูกกับสไตล์ที่โปรแกรมเล่นจริง เพราะความชำนาญคิดจากเหตุการณ์การรบอยู่แล้ว
- **D — ตำราสกิล:** บอสหอคอยและมอน EX ดรอปตำราด้วยโอกาสต่ำ **พร้อมเพดานดวง** (ล้มบอสตัวเดิมครบ N ครั้งได้แน่นอน)
  ดวงจึงตัดสินแค่ว่า "ได้เร็วหรือช้า" ไม่ใช่ "ได้หรือไม่ได้" · สกิลกลุ่มนี้ต้องมีระบบสถานะใหม่ใน engine จึงอยู่ระยะสุดท้าย

### 7.2 ช่องสกิล (ต้องตัดสินก่อน S3)

เมื่อครบทุกระยะ ผู้เล่นหนึ่งคนอาจมีสกิลเกิน 30 ตัว · เสนอ **จำกัดจำนวนสกิลที่ใช้ในโปรแกรมเดียว** (เช่น 3 ตัวตอนเริ่ม เพิ่มตามเลเวล ถึง 6)
ให้ตัวตรวจโปรแกรมฟ้องเมื่อใช้เกิน — เป็นรูปแบบที่เบากว่างบ Memory (MB) ของเฟส 2 แต่ได้ผลเดียวกัน คือต้องเลือกว่าจะพกอะไร
S1 และ S2 ยังไม่ต้องมีช่องนี้ (สกิลรวมไม่เกิน 8 ตัวต่ออาชีพ)
