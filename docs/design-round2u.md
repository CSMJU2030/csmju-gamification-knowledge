# รอบ 2U — เปลี่ยนโทน UI ทั้งเกม

> สัญญาที่ทุกคนยึดในรอบนี้ | PM เป็นเจ้าของ | 21 ก.ย. 2026
> อ้างอิงที่เจ้าของโปรเจกต์เลือก: **Hollow Knight: Silksong** (gameuidatabase.com id 2178)

---

## 1. เอาอะไรมา เอาอะไรไม่เอา

เจ้าของโปรเจกต์บอกว่า "เปลี่ยนเป็นโทนแบบนี้ทั้งหมด ปรับเป็นแบบของเราก็ได้"
คำว่า **"แบบของเรา"** คือเส้นแบ่งของรอบนี้ และแปลว่า:

| | เอา | ไม่เอา |
|---|---|---|
| โครงหน้า | เต็มจอ ไม่มีกล่องครอบ | การ์ด/แผงซ้อนการ์ด |
| การแบ่งส่วน | เส้นบาง + ที่ว่าง | ขอบหนา + เงาแข็ง |
| ป้ายกำกับ | วางบนเนื้อหาโดยตรง ตัวเล็ก เว้นอักษรกว้าง | แคปซูลลอยเหนือของ |
| ลวดลาย | มุมวิจิตรเส้นเดียว บาง จาง | ลายเต็มกรอบ |
| **สี** | **ทอง/มิ้นต์ของเราเหมือนเดิม** | **แดงเลือดหมูของ Silksong** |
| ตัวอักษร | ฟอนต์เดิม + เว้นอักษร + ขนาดเล็กลง | ฟอนต์ serif วิจิตร |
| คอนทราสต์ | อ่านออกกลางแดด | เทาเข้มบนดำเกือบสนิท |

**ทำไมไม่เอาสีแดง** — แผนที่โลกที่เจนมาเป็นภาพสีสดเต็มใบ ถ้าล้อมด้วย UI สีเลือด
ภาพจะกลายเป็นสิ่งแปลกปลอมกลางฉากสยองขวัญ และมอนพิกเซลของเราเป็นโทนสดใส
สีทอง/มิ้นต์ที่มีอยู่เข้ากับทั้งสองอย่างอยู่แล้ว — สิ่งที่เกมเราขาดคือ *โครง* ไม่ใช่ *สี*

## 2. กฎเหล็กสามข้อ (ห้ามผิดแม้แต่หน้าเดียว)

### 2.1 พื้นผิวหลักไม่มีกล่อง

แผนที่ · ฉากต่อสู้ · หน้าประกาศ · หน้าสรุปผล · หน้าดวล
= เนื้อหาลอยบน `--bg-deep` ตรง ๆ แยกส่วนด้วย **เส้นบางกับที่ว่าง** เท่านั้น

ห้ามใช้ `.pixel-panel` / `.pixel-cell` บนพื้นผิวเหล่านี้ (ยังใช้ได้กับหน้ากระเป๋า/ตัวละคร
ที่เป็นตารางข้อมูลจริง ๆ ซึ่งการมีช่องช่วยให้อ่านง่ายขึ้น ไม่ใช่รกขึ้น)

**นี่คือข้อที่แก้ปัญหาที่วัดได้จริง:** หน้าแผนที่ตอนนี้ยัดภาพลงการ์ดแล้วเหลือที่ว่างครึ่งจอ

### 2.2 คอนทราสต์ขั้นต่ำ — จุดอ่อนของ Silksong ที่เราจะไม่ลอกมา

- ตัวหนังสือเนื้อหา **≥ 4.5:1** เทียบพื้นหลัง
- ป้ายกำกับ/ของประดับ **≥ 3:1** และ **ห้ามเล็กกว่า 12px**
- ห้ามสื่อสารสถานะด้วยสีอย่างเดียว ต้องมีรูปทรง/ไอคอน/ตัวหนังสือกำกับด้วยเสมอ
  (หมุดบนแผนที่ตอนนี้แยกกันด้วยสีล้วน — เปิดโหมดขาวดำแล้วแยกไม่ออก)

เหตุผล: Silksong เล่นบนทีวี/จอเดสก์ท็อปในห้องมืด เกมเราเล่นบนมือถือกลางแดด
และผู้เล่นกลุ่มเป้าหมายคือเด็กที่กำลังหัดเขียนโปรแกรม ไม่ใช่คนที่ยอมเพ่ง

### 2.3 ภาษาไทยไม่มีตัวพิมพ์ใหญ่

Silksong สร้างลำดับชั้นด้วย SMALL CAPS ซึ่งภาษาไทยทำไม่ได้
ของเราใช้สามอย่างแทน: **เว้นอักษร 0.08em + ขนาดเล็กลงหนึ่งขั้น + สีทองหม่น + เส้นคั่นบาง**
ห้ามใช้ `text-transform: uppercase` เพราะมันไม่มีผลกับไทยแต่ไปทำให้คำอังกฤษปนดูแปลก

## 3. ข้อยกเว้นข้อเดียว: พื้นที่โค้ด

`.code-surface` (เอดิเตอร์ BloxCode · แผงโค้ดในฉากต่อสู้ · โค้ดของคู่ต่อสู้)
**คงพื้นทึบ monospace เลขบรรทัด สีไวยากรณ์ และคอนทราสต์เต็มไว้เหมือนเดิม**

โทนใหม่ใช้ได้แค่กับ *กรอบ* ของหน้านั้น — หัวข้อ ปุ่ม แผงข้อผิดพลาด พาเลตบล็อก

เหตุผลเชิงกลไก ไม่ใช่รสนิยม: โทนนี้คือ "ตัวหนังสือน้อย ๆ ลอยบนความมืด"
ส่วนเอดิเตอร์ต้องการตัวหนังสือแน่นและอ่านทีละตัวอักษร ถ้าเอาโทนลงไปในพื้นที่โค้ด
สิ่งที่เสียคือความสามารถหลักของเกม ไม่ใช่แค่ความสวย

## 4. ชิ้นส่วนกลาง (PM เขียนเอง — ห้ามเขียนซ้ำในหน้าใดหน้าหนึ่ง)

| ชิ้น | ใช้เมื่อไร |
|---|---|
| `<Ornament />` | มุมวิจิตรสี่มุมของพื้นผิวหลัก — SVG ตัวเดียว หมุนเอา ไม่ใช่วาดสี่ครั้ง |
| `.tone-stage` | พื้นผิวเต็มจอไม่มีกล่อง + แสงฟุ้งทองจาง ๆ ตรงกลาง |
| `.tone-veil` | ม่านทับฉากหลังตอนมีโมดัล (แทนพื้นแผงทึบ) |
| `.tone-title` | ชื่อเรื่องกลางจอ ตัวใหญ่ น้ำหนักบาง เว้นอักษร |
| `.tone-label` | ป้ายกำกับตามกฎ §2.3 |
| `.tone-rule` | เส้นคั่นบางที่จางหายทั้งสองปลาย |
| `.tone-list` | รายการที่คั่นด้วยเส้นบาง ไม่ใช่การ์ด |
| `.code-surface` | ข้อยกเว้น §3 |

ถ้าหน้าไหนต้องเขียนเงา/ขอบ/ลายเอง แปลว่าชิ้นส่วนกลางยังขาด — บอก PM ให้เพิ่ม
อย่าเขียนเฉพาะกิจ เพราะโทนที่เพี้ยนทีละหน้าคือสิ่งที่ทำให้ UI ดู "ทำมาเล่น" ตั้งแต่แรก

## 5. เกณฑ์รับงาน

| # | เกณฑ์ | วัดยังไง |
|---|---|---|
| U1 | ไม่มี `.pixel-panel`/`.pixel-cell` เหลือบนพื้นผิวหลักตาม §2.1 | `grep` ในไฟล์ของหน้านั้น |
| U2 | คอนทราสต์ผ่าน §2.2 ทุกคู่สีที่ใช้จริง | คำนวณจากค่าสีที่เรนเดอร์จริง |
| U3 | ทุกหน้าถ่ายที่ 1280px และ 390px แล้ว **PM เปิดดูเอง** | ภาพ ไม่ใช่คำรายงาน |
| U4 | พื้นที่กดยังไม่ต่ำกว่า 44px และไม่มีเลื่อนแนวนอน | วัดจาก DOM จริง |
| U5 | พื้นที่โค้ดไม่ถูกแตะตาม §3 | เทียบภาพก่อน/หลังของหน้า BloxCode |
