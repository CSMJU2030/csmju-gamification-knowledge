# มอนของโจทย์ — อาจารย์ออกแบบมอนให้นักศึกษาสู้

สถานะ: **ตกลงแล้ว 7 ต.ค. 2569** · ต่อยอด D4 ใน [`design-csmju-migration.md`](design-csmju-migration.md) (อาจารย์ตั้งโจทย์ BloxCode)
แบ่ง 2 PR: **A** engine + backend + API (เอกสารนี้ข้อ 1–6) · **B** หน้าเว็บ (ข้อ 7)

## 1. ทำไม

โจทย์ตอนนี้บอกแค่ "ให้โปรแกรมทำอะไร" แต่ไม่มีอะไรให้ลองว่าโปรแกรมทำได้จริงหรือยัง ·
มอนของโจทย์ทำให้อาจารย์ตั้ง **สถานการณ์** ได้เอง เช่น มอนเลือดเยอะแต่ตีเบา (สอนเรื่องจังหวะใช้สกิล) ·
มอนที่ตีแรงเมื่อเลือดน้อย (สอน `if`) · ฝูงเล็กหลายตัว (สอนเลือกเป้า) แล้วนักศึกษาเขียนโปรแกรมของตัวเองไปสู้

## 2. ตัดสินใจแล้ว

| ข้อ | ตัดสินใจ | เหตุผล |
|---|---|---|
| M1 | มอนผูกกับโจทย์ **1–4 ตัว เวฟเดียว** · โจทย์ที่ไม่มีมอนยังใช้ได้เหมือนเดิม | เวฟเดียวพอสำหรับตั้งสถานการณ์ · ไม่ต้องออกแบบหลายเวฟ |
| M2 | เริ่มจาก **ต้นแบบ 10 ตัวที่มีภาพอยู่แล้ว** (`monsterArchetypes`) แล้วปรับ ชื่อ · เลเวล · ตัวคูณ HP · ตัวคูณดาเมจ · สกิล | ไม่ต้องอัปโหลดภาพ · สเตตัสคิดด้วยสูตรเดียวกับมอนในหอคอย |
| M3 | อาจารย์เขียน **โปรแกรม BloxCode ให้มอนได้ ไม่บังคับ** · ไม่เขียน = พฤติกรรมตามบทบาทของต้นแบบ (`monsterPrograms`) | ตรวจด้วย parser + validator ตัวเดียวกับของผู้เล่น (เปิดไวยากรณ์ทุกชุด · สกิลเท่าที่มอนตัวนั้นมี) · ถูกจำกัดงบต่อเทิร์นเหมือนกัน |
| M4 | **ชนะครั้งแรกได้ EXP และทองเล็กน้อย** ครั้งต่อไปไม่ได้อะไร · แพ้ไม่ได้อะไร · ไม่มีของดรอป | กันฟาร์ม: รางวัลคิดจาก **เลเวลของผู้เล่น** ไม่ใช่จากมอนที่อาจารย์ตั้ง (ตั้งมอนอ่อนก็ไม่ได้รางวัลมากขึ้น) |
| M5 | **อาจารย์เจ้าของโจทย์และผู้ดูแลดูผลได้** ว่าใครสู้กี่ครั้ง ชนะแล้วหรือยัง (แสดงชื่อในเกม = รหัสนักศึกษา) · นักศึกษาเห็นผลของตัวเองเท่านั้น | อาจารย์ใช้ติดตามการเรียน · ไม่เปิดผลของคนอื่นให้นักศึกษาเห็น |
| M6 | การรบกับมอนของโจทย์ **ไม่นับ** ความคืบหน้าหอคอย/ภูมิภาค · ไม่เพิ่มงานสะสมของสเตตัส · ไม่อยู่ในประวัติการรบ (`battles`) | เป็นสนามฝึก ไม่ใช่ทางลัดของความคืบหน้า · ผลเก็บแยกใน `challenge_attempts` |

## 3. ขอบเขตค่าที่อาจารย์ตั้งได้ (`CHALLENGE_MONSTER_LIMITS` ใน engine)

| ช่อง | ค่า |
|---|---|
| จำนวนมอนต่อโจทย์ | 0–4 |
| `name` | 1–40 ตัวอักษร |
| `archetypeId` | ต้นแบบใน `gamedata.monsterArchetypes` |
| `level` | 1–50 |
| `hpMult` | 0.5–5 |
| `dmgMult` | 0.5–3 |
| `skills` | 1–3 ตัวจาก `mon_bite` (กัด) · `mon_dark_bolt` (ศรมืด) · `mon_roar` (คำราม) — ไม่ส่ง = สกิลของต้นแบบ |
| `programSource` | ไม่บังคับ · ยาวไม่เกินโปรแกรมของผู้เล่น · ต้องแปลและตรวจผ่าน |

`mon_windup` / `mon_crush` (ท่าตั้งท่าทุบ) เป็นกลไกของโซน ไม่เปิดให้เลือกในรอบนี้

## 4. รางวัลชนะครั้งแรก (`challengeReward(level)`)

- EXP = 10% ของ EXP ที่ต้องใช้ขึ้นเลเวลถัดไป ณ เลเวลของผู้เล่นตอนชนะ (`expToNext(level) × 0.1` ปัดเศษ อย่างน้อย 1)
- ทอง = `15 + 9 × level` (ราวสามเท่าของมอนหนึ่งตัวที่เลเวลเดียวกัน)
- ได้ครั้งเดียวต่อตัวละครต่อโจทย์ — ตรวจในทรานแซกชันเดียวกับที่บันทึก (ล็อกแถวตัวละคร) สองคำขอพร้อมกันจึงได้รางวัลครั้งเดียว

## 5. API

| method | path | ใครใช้ | หมายเหตุ |
|---|---|---|---|
| `POST` · `PATCH` | `/api/v1/challenges` · `/api/v1/challenges/:id` | ผู้สอน · ผู้ดูแล | เพิ่มช่อง `monsters` (array 0–4) · PATCH ที่ส่ง `monsters` = แทนทั้งชุด · ไม่ส่ง = คงเดิม |
| `GET` | `/api/v1/challenges/:id` | ทุกคน | เพิ่ม `monsters` และ `myResult` (`attempts` · `cleared` · `firstClearedAt`) ของผู้เรียก |
| `POST` | `/api/v1/battles` `{ challengeId }` | ผู้เล่นที่มีตัวละคร | สู้กับมอนของโจทย์ · ส่งได้อย่างเดียวจาก `towerFloor` / `regionRunId` / `challengeId` · โจทย์ไม่มีมอน → 409 |
| `GET` | `/api/v1/challenges/:id/attempts` | ผู้สอนเจ้าของโจทย์ · ผู้ดูแล | รายคน: ชื่อในเกม · จำนวนครั้ง · ชนะแล้วไหม · ชนะครั้งแรกเมื่อไร · แบ่งหน้าตามมาตรฐาน · คนอื่นได้ 403 |

สิทธิ์ใช้ชุดเดิม: แก้มอน = สิทธิ์แก้โจทย์ (`challenge:update:own` / `:any`) · ดูผล = เจ้าของโจทย์ที่มี `challenge:update:own` หรือผู้ที่มี `challenge:update:any` ·
สู้ = `battle:create:own`

## 6. ข้อมูล

- `challenge_monsters` — `challenge_id` (ลบโจทย์ = ลบมอน) · `position` · `name` · `archetype_id` · `level` · `hp_mult` · `dmg_mult` · `skills` · `program_source`
- `challenge_attempts` — `challenge_id` · `character_id` · `is_victory` · `rounds` · `exp_gained` · `gold_gained` · `created_at` (ลบโจทย์หรือตัวละคร = ลบผล)
- migration เพิ่มตารางอย่างเดียว ไม่มี `CREATE EXTENSION` (deployment.md ข้อ 4.1)

## 7. หน้าเว็บ (PR B)

- ฟอร์มโจทย์มีส่วน "มอนของโจทย์": เพิ่ม/ลบได้ถึง 4 ตัว · เลือกต้นแบบพร้อมภาพ · ชื่อ · เลเวล · ตัวคูณ · สกิล · โปรแกรม (ไม่บังคับ) · ปุ่มทดลองสู้
- หน้าโจทย์: การ์ดมอน · ปุ่ม "สู้กับมอนของโจทย์" → ฉากรบตัวเดียวกับหอคอย · ผลของตัวเอง · รางวัลชนะครั้งแรก
- ผู้สอนเจ้าของโจทย์เห็นตาราง "ผลของผู้เล่น"
