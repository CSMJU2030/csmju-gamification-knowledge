# BloxCode — เอกสารอ้างอิงภาษา (เฟส 2B-1)
> สัญญาที่ทุกทีมต้องยึด | PM เป็นเจ้าของ | 9 ก.ย. 2026
> โครงสร้างข้อมูลจริงอยู่ที่ `engine/src/lang/spec.ts` — เอกสารนี้อธิบาย "ทำไม" และ "ใช้ยังไง"

## 1. BloxCode คืออะไร

ภาษาย่อยของ Python ที่เราเขียนล่ามเอง ผู้เล่นพิมพ์ **ไวยากรณ์ Python จริง** แต่เรารองรับเฉพาะคำสั่งที่เกมใช้

ทำไมไม่รัน Python จริง — 4 เหตุผลที่ตัดสินใจไปแล้ว:
1. **ความปลอดภัย** — โค้ดรันฝั่งเซิร์ฟเวอร์เพื่อกันโกง การรัน Python ผู้ใช้บนเซิร์ฟเวอร์คือช่องโหว่ระดับยึดเครื่อง
2. **Deterministic** — seed เดิม + โปรแกรมเดิม = ผลเดิมเสมอ (จำเป็นต่อ replay และเทสต์ balance อัตโนมัติ)
3. **หยุดได้เสมอ** — มีงบโหนด `NODE_BUDGET_PER_TURN` เกินแล้วตัดจบ ไม่มีทาง infinite loop
4. **แปลงกลับเป็นบล็อกได้** — เพราะ AST เป็นของเรา จึงซิงก์บล็อก ⟷ ข้อความสองทางได้แม่นยำ

## 2. รูปแบบโปรแกรม

```python
# เกมเรียก turn() ให้ 1 ครั้งต่อเทิร์นของเรา
def turn():
    if me.hp_pct < 30:
        cast("heal", me)
    elif count(enemies) >= 3:
        cast("blizzard", enemies)
    else:
        attack(weakest(enemies))
```

- ต้องมี `def turn():` เพียงตัวเดียว ห้ามมีฟังก์ชันอื่น (เฟสนี้)
- การเยื้อง **4 ช่อง** ต่อระดับ (รับ tab ได้ แต่ formatter จะแปลงเป็น space)
- ยาวได้ไม่เกิน `MAX_PROGRAM_LINES` บรรทัด

## 3. API

| กลุ่ม | รายการ | หมายเหตุ |
|---|---|---|
| ตัวแปร | `me` `enemies` `allies` `turn_no` | `enemies`/`allies` เป็นลิสต์ของตัวที่ยังไม่ตาย |
| `me.` | `hp` `mp` `hp_pct` `mp_pct` `level` `atk` `matk` `defense` `magic_defense` `speed` | `*_pct` เป็น 0–100 · ใช้ `defense` ไม่ใช่ `def` เพราะ `def` เป็นคำสงวนของ Python |
| หน่วยอื่น `.` | `hp` `hp_pct` `level` `atk` `speed` | |
| เลือกเป้า | `weakest(l)` `strongest(l)` `deadliest(l)` `fastest(l)` `random_of(l)` | คืน 1 ตัว · `deadliest` = ATK สูงสุด |
| ตรวจสอบ | `count(l)` `len(l)` `has_buff(s)` `has_debuff(s)` `can_cast(s)` | `has_buff`: `taunt` `shield` · `has_debuff`: `marked` (รอบ 2M — มอนตั้งท่าหมายหัวเรา เทิร์นหน้าของมันจะทุบ) · ชื่ออื่น = ValueError |
| **การกระทำ** | `attack(t)` `cast(name, t)` `defend()` `wait()` | จบเทิร์น เรียกซ้ำนับครั้งแรก |

**กฎการทำงานที่ต้องทำให้ตรงกันทุกฝั่ง:**
- โปรแกรมวิ่งจบโดยไม่เรียก action → ทำ `attack(weakest(enemies))` อัตโนมัติ (`usedFallback: true`)
- `cast` สกิลที่ยังไม่มี หรือ MP ไม่พอ → **ข้ามคำสั่งนั้น ไม่เสียเทิร์น** แล้วบันทึกคำเตือน
- `cast(name, enemies)` (ส่งลิสต์) ใช้ได้เมื่อสกิลนั้นเป็น AoE ไม่งั้นเป็น `TypeError`
- `random_of` ใช้ rng ของการต่อสู้ จึงยัง deterministic

## 4. ไวยากรณ์ที่ปลดล็อกตามชั้น

หลักสูตรซ่อนในเกม — ผู้เล่นได้ไวยากรณ์ใหม่เมื่อผ่านชั้น ไม่ใช่เจอทั้งหมดตั้งแต่นาทีแรก

ค่าจริงอยู่ที่ `FEATURE_UNLOCK` ใน `packages/engine/src/lang/spec.ts` (ตารางนี้ต้องตรงกับไฟล์นั้น)

| ผ่านชั้น | ฟีเจอร์ | ได้เรียนเรื่อง |
|---|---|---|
| เริ่มเกม | `def turn():` · เรียกฟังก์ชัน · การเยื้อง | โครงสร้างฟังก์ชัน |
| 1 | `if` / `else` · `< > <= >= == !=` | เงื่อนไข |
| 1 | ข้อความ `"..."` → `cast("firebolt", t)` · `has_debuff("marked")` | argument และ string (ย้ายจากชั้น 2 ในรอบ B ให้ใช้สกิลได้ทันทีที่เลือกอาชีพ) |
| 3 | `elif` | หลายทางเลือก |
| 4 | `and` `or` `not` | ตรรกะบูลีน |
| 5 | `+ - * /` · `len()` | การคำนวณ |
| 6 | ตัวแปร `t = weakest(enemies)` | ตัวแปร |
| 8 | `for x in enemies:` | การวนซ้ำ |

ใช้ฟีเจอร์ที่ยังไม่ปลดล็อก → `LockedFeatureError` พร้อมบอกว่าต้องผ่านชั้นไหน

### คำสงวนของ Python (แก้ 19 ก.ย. 2026)

เดิม tokenizer ปล่อยทุกคำที่หน้าตาเป็นชื่อผ่านเป็น `NAME` รวมคำสงวนด้วย
ผลคือ `me.def` **parse ผ่าน** ในล่ามเรา แล้วไปโผล่เป็น `NameError` ตอน validate
ทั้งที่ CPython ปฏิเสธด้วย `SyntaxError` ตั้งแต่ต้น — ผิดกติกาเหล็กเต็ม ๆ
(ที่เจอเพราะ client tsconfig เปิด `noUnusedLocals` แล้วฟ้องว่า `KEYWORDS` กับ
`KEYWORD_RENAMES` เป็นโค้ดตาย ซึ่งเป็น "อาการ" ของบั๊กนี้พอดี)

ตอนนี้คำสงวนเป็น token คนละชนิด (`KEYWORD`) จุดที่ต้องการชื่อจะขอ `NAME` เสมอ
จึงปฏิเสธเชิงโครงสร้าง ไม่ใช่เพราะใครจำได้ ครอบคลุม 6 ตำแหน่ง: หลังจุด, เป้าการกำหนดค่า,
ตัวแปรของ for, ชื่อฟังก์ชันที่เรียก/ประกาศ, ตัวถูกวน, และเป็นค่าเปล่า ๆ

ระหว่างแก้พบเพิ่มว่า **มีคำสงวนอีก 7 คำที่ไม่เคยถูกตรวจเลย**
(`as` `async` `await` `except` `finally` `from` `nonlocal`) — บั๊กเดียวกับ `me.def` คนละคำ
ตอนนี้เทสต์ดึงรายการจาก `keyword.kwlist` ของ CPython ตัวจริงมาไล่ จึงกันคำที่จะเพิ่มในอนาคตด้วย

**`True` / `False` / `None` — ปฏิเสธด้วย SyntaxError ที่บอกเหตุผล (PM ตัดสิน 19 ก.ย. 2026)**
เพราะ `Expr` ใน spec.ts ยังไม่มีชนิดสำหรับค่าบูลีน/None การรองรับจริงต้องเพิ่มชนิดใน union
(กระทบ parser, printer, evaluator, validate, shim, differential test)
ทางลัดอย่างแปลง `True` เป็น `num 1` ห้ามทำ เพราะพัง round-trip — printer จะพิมพ์ `1` กลับมา

ทิศทางที่กติกาเหล็กห้ามคือ "เรารับแต่ CPython ไม่รับ" ซึ่งตอนนี้เหลือ **0 เคส**
จาก 950 เคสที่ไล่ (38 คำ × 25 ตำแหน่ง) ส่วนทิศตรงข้าม (CPython รับแต่เราไม่รับ) เป็นธรรมชาติ
ของภาษาย่อยอยู่แล้ว — เราก็ไม่รับ `while` `import` `x in y` `x is y` เหมือนกัน
**แต่** `if can_cast("heal") == True:` เป็นท่าที่มือใหม่เขียนบ่อยมาก และ `can_cast`/`has_buff`
ของเราเองก็คืนค่าบูลีน จึงจัดเป็นงานรอบ 2B-3 ไม่ใช่ปล่อยทิ้ง

## 5. ข้อความ error

ชื่อ error เป็นอังกฤษเหมือน Python จริง (ผู้เล่นจะได้ไม่ตกใจตอนไปเขียน Python จริง) คำอธิบายเป็นไทย

```
IndentationError — บรรทัด 5
    การเยื้องไม่ถูกต้อง: ต้องเยื้องเข้าไป 4 ช่องหลัง if

NameError — บรรทัด 3
    ไม่รู้จัก 'enemys' — คุณหมายถึง 'enemies' หรือเปล่า?

LockedFeatureError — บรรทัด 6
    ตัวเชื่อม and / or / not ยังไม่ปลดล็อก — ต้องผ่านชั้น 6 ก่อน

MemoryError
    โปรแกรมนี้ใช้ 23 MB แต่คุณมี 20 MB — เอาสกิลออกหรืออัพเลเวลก่อน
```

กติกา: ทุก error ต้องบอก **บรรทัด** เสมอ และถ้าเดาเจตนาได้ให้เสนอทางแก้ (เช่นชื่อใกล้เคียง)

### `pass` ในบล็อกว่าง (แก้ 19 ก.ย. 2026)

`toPython()` เคยเติม `pass` ให้เฉพาะตอน `turn()` ทั้งก้อนว่าง ทำให้ `if`/`for` ที่ body ว่าง
ถูกพิมพ์ออกมาเป็นโค้ดที่ parse ตัวเองไม่ผ่าน (`IndentationError`)
เจอตอนผู้เล่นลบบล็อกสุดท้ายข้างใน `if` — ย้ายมากันที่ printer แล้ว
เพราะเป็นกับดักของทุกคนที่สร้าง AST เอง ไม่ใช่แค่เอดิเตอร์ (`fromRules`, โปรแกรมมอนในรอบ 2C)

**กติกา: printer ต้องคายโค้ดที่ parse กลับได้เสมอ ไม่มีข้อยกเว้น**

## 6. Memory (MB)

- ตัวละครมี `6 + floor(level/3)` MB
  (แก้ 9 ก.ย. 2026 จากเดิม `10 + level/2` — สูตรเดิมไม่เคยบีบใครเลย ทุกอาชีพใส่สกิลครบชุดได้
  ทำให้ปุ่ม balance หลักกลายเป็นของประดับ · สูตรใหม่บังคับให้เลือก เช่น นักรบ lv10 มี 9 MB
  แต่สกิลครบชุดกิน 13 MB)
- นับเฉพาะสกิลที่ **ถูกอ้างถึงในโปรแกรม** — มีบล็อกแต่ไม่ได้ใช้ ไม่กิน MB
- `attack` `defend` `wait` และเงื่อนไขทั้งหมด = ฟรี
- สกิลเดียวกันเรียกหลายที่ = นับครั้งเดียว

นี่คือปุ่มปรับ balance หลัก แก้ตัวเลขใน `SKILL_MEMORY_COST` ได้โดยไม่แตะโค้ด

## 8. มอนสเตอร์ใช้ภาษาเดียวกัน

AI ของมอนสเตอร์คือโปรแกรม BloxCode ที่เก็บใน `gamedata.json` (`monsterPrograms`)
ข้อดี: ปรับ balance ได้โดยไม่แตะโค้ด · ผู้เล่นเปิดดูโค้ดมอนได้ (ฟีเจอร์เรียนรู้ในรอบ 2B-3) · ทดสอบด้วยเครื่องมือชุดเดียวกัน

**สถานะปัจจุบัน (9 ก.ย. 2026):** โปรแกรมของทั้ง 5 บทบาทยังเหมือนกันโดยตั้งใจ — เขียนให้ใช้ RNG
ตรงจุดเดิมกับกฎเก่าเป๊ะ ๆ เพื่อให้ balance ไม่ขยับเลยตอนย้ายระบบ (มีเทสต์ยืนยันว่าผลการรบ
เหมือนเดิมทุกไบต์) การทำให้แต่ละบทบาทเล่นต่างกันจริงเป็นการแก้ไฟล์ข้อมูลล้วน ๆ ไม่ต้องแตะโค้ด
**PM เลื่อนไปทำในรอบ 2C** พร้อมกับตอนเพิ่มระบบสถานะ (พิษ/มึน/บัฟ) เพราะรอบนั้นต้องจูน balance
ใหม่ทั้งชุดอยู่แล้ว — ทำตอนนี้เท่ากับต้องจูนสองรอบ

**รอบ 2M (23 ก.ย. 2026):** สถานะร้ายตัวแรกมาจาก *กลไกของโซน* ไม่ใช่จากโปรแกรมมอน —
โกเลมที่ดินแดนน้ำแข็งตั้งท่าหมายหัวตามจังหวะที่ engine คุม (`RegionMechanic` · battle.ts `windup`)
แล้ว `has_debuff("marked")` เป็นจริงจนกว่ามันจะทุบ เหตุผลที่ไม่เขียนเป็นโปรแกรมมอน: จังหวะต้องสุ่มครั้งเดียวต่อเวฟ
และต้องการันตีว่าผู้เล่นได้ลงมือหนึ่งครั้งก่อนโดนทุบ ซึ่งภาษาของมอนแสดงออกไม่ได้ (docs/design-round2m.md)
