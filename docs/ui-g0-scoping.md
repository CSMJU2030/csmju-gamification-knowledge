## 3. รายการหน้าจอ

| route | มาหน้านี้เพื่อ… | API | loading | empty | error พิเศษ |
|---|---|---|---|---|---|

### 3.1 การเข้าใช้ครั้งแรก

```text
Dashboard ของ Core Hub → คลิก Code Tower
 → Core Hub SSO authorize → 302 → backend GET /auth/callback (ตั้งคุกกี้ HttpOnly)
 → 302 → frontend /            (SSO_SUCCESS_REDIRECT)
 → GET /characters/current = 404 → ฟอร์ม "ตั้งชื่อตัวละคร" (ช่องเดียว + ปุ่ม "เริ่มเล่น")
 → POST /characters = 201 → หน้า "ตัวละคร" + การ์ดแนะนำ "ลองรบชั้น 1"
```

| องค์ประกอบ | PLAYER (student · alumni) | INSTRUCTOR (staff) | ADMIN (admin) |
|---|---|---|---|
| เมนู 1–7 | ✅ | ✅ | ✅ |

| ปุ่มแก้/ลบบนโจทย์ | **ซ่อน** | ✅ เฉพาะโจทย์ของตัวเอง · ของคนอื่น **ซ่อน** | ✅ ทุกโจทย์ |
| badge บทบาทบน PageHeader ของหน้าแรก | "นักศึกษา" / "ศิษย์เก่า" | "บุคลากร/อาจารย์ · ผู้สอน Code Tower" | "ผู้ดูแลระบบ · ผู้ดูแล Code Tower" |

UI ตัดสินจาก `GET /api/v1/me` → `permissions` (ไม่ใช่จาก role ตรง ๆ) · การบังคับสิทธิ์จริงอยู่ที่ backend เสมอ

**disable + เหตุผล (มีสิทธิ์แต่ตอนนี้ทำไม่ได้)** — ข้อความมาจากกฎของเกม ตรงกับที่ backend ตอบ 409:

| ปุ่ม | เงื่อนไข | เหตุผลที่แสดง |
|---|---|---|
| เลือกอาชีพ | ยังไม่ผ่านชั้น 1 | "ต้องผ่านชั้น 1 ก่อนถึงจะเลือกอาชีพได้" |
| ท้าทายชั้น N | N > ชั้นถัดไปของหอคอย | "ต้องผ่านชั้น N-1 ก่อน" |
| เข้าโซน | ยังไม่ปลดล็อก | "ต้องผ่านความยาก X ก่อน" |
| เข้ารอบ d | d > maxDepthAllowed | "ตอนนี้เข้าได้ถึงรอบที่ m" |
| ตีบวก | ทองหรือวัสดุไม่พอ / +15 แล้ว | "ต้องใช้ G ทอง และ M วัสดุ" / "ถึงขั้นสูงสุดแล้ว" |
| ย่อย | สวมอยู่ | "ถอดก่อนถึงจะย่อยได้" |

## 5. เวทีเกม (ขอบเขตของคำขอ D1)

### 5.1 อะไรคือเวทีเกม

| ชิ้น | ทำไมต้องอยู่นอกกฎสีของ UI |
|---|---|
| ฉากรบ (canvas · sprite pixel art · เอฟเฟกต์) | สีของ sprite คือภาพวาด ไม่ใช่สีของ UI |
| ภาพแผนที่โลก + วง hotspot บนภาพ | ภาพประกอบ — มาตรฐานเปิดให้แผนที่อิสระอยู่แล้ว (ข้อ 1) |
| บล็อก BloxCode ในเอดิเตอร์ | สีบอกชนิดคำสั่งแบบ Scratch/Blockly |
| portrait ของตัวละครและมอน | ภาพ pixel art |

### 5.2 อะไร **ไม่ใช่** เวทีเกม (ใช้ token และ component กลาง 100%)

การ์ดสเตตัส · แถบ EXP · ตารางไอเทม · ปุ่มทุกปุ่ม (รวม "เริ่มรบ" "ข้าม" "เล่นซ้ำ") · ฟอร์ม · modal · toast · badge rarity · บันทึกการรบแบบข้อความ · แผงข้อผิดพลาดของโปรแกรม · รายการโซน/ชั้น · หน้าผลการรบ

### 5.3 เวทีเกมอยู่ในหน้าอย่างไร

- อยู่ **ในการ์ดมาตรฐาน** (`cardClass`) ภายในพื้นที่เนื้อหาของ AppShell — ไม่เต็มจอ ไม่ทับ sidebar/top bar
- ขนาดคงที่ตามอัตราส่วน (16:9 บน desktop · 4:3 บนมือถือ) กำหนดความสูงล่วงหน้า กัน CLS
- ควบคุมด้วยปุ่มมาตรฐานใต้เวที: เล่น/หยุด · ข้ามไปผลลัพธ์ · ความเร็ว 1×/2× — ใช้คีย์บอร์ดได้ (Space/→/Esc)
- `prefers-reduced-motion`: ข้ามแอนิเมชันกลางเทิร์น แสดงผลทีละเทิร์นแบบภาพนิ่ง
- ทุกเหตุการณ์ในฉากมี **บันทึกการรบแบบข้อความ** คู่กัน (อ่านด้วย screen reader ได้ · `aria-live="polite"`)
- โหลดแบบ lazy เฉพาะหน้า `/battle` และ `/world` (renderer + sprites ≈ 140KB ดิบ) เพื่อให้ JS แรกเข้า ≤ 250KB gzip

## 6. error.code → UI (ตามข้อ 9.3 + ความหมายในเกม)

| code | ในเกมเกิดเมื่อ | แสดง |
|---|---|---|
| `UNAUTHORIZED` | คุกกี้หมดอายุ (15 นาที) | ไม่แสดงอะไร — AppShell พากลับ SSO (ตามข้อ 9.3) |
| `FORBIDDEN` | role เข้าไม่ได้ · แตะโจทย์ของคนอื่น | หน้า/การ์ด "ไม่มีสิทธิ์" ข้อความมาตรฐาน |
| `NOT_FOUND` | ยังไม่มีตัวละคร · รอบหมดอายุไปแล้ว · โจทย์ถูกลบ | ตัวละคร → ฟอร์มสร้าง (ข้อ 3.1) · อื่น ๆ → EmptyState + ย้อนกลับ |
| `VALIDATION_ERROR` | โปรแกรมผิด · ชื่อตัวละครผิดรูป | โปรแกรม → ไฮไลต์บรรทัด + แผงข้อผิดพลาด · ฟอร์ม → ใต้ฟิลด์ |
| `CONFLICT` | กฎของเกม (ข้อ 4 ตารางล่าง) · สู้รอบนี้ไปแล้ว | alert inline ข้อความจาก backend + ทางไปต่อ ("เข้ารอบใหม่") |
| `INTERNAL_ERROR` | — | ErrorState + "ลองอีกครั้ง" |

## 8. งบประสิทธิภาพ (ข้อ 15)

| รายการ | แผน |
|---|---|
| JS แรกเข้า ≤ 250KB gzip | เวทีเกมและเอดิเตอร์บล็อกแยก chunk โหลดเฉพาะ route ที่ใช้ · engine (ตัวตรวจโค้ด) โหลดเฉพาะ `/program` |
| LCP ≤ 2.5s | หน้าแรกเป็นการ์ดข้อความ ไม่มีภาพใหญ่ · แผนที่ใช้ `worldmap-small.jpg` (110KB) บนมือถือ |
| CLS ≤ 0.1 | เวทีเกมมีขนาดจองล่วงหน้า · skeleton ขนาดเท่าของจริง |
| ฟอนต์ ≤ 4 ไฟล์ | ใช้ชุดของ template (Noto Sans Thai + Plus Jakarta Sans) · เลิกฟอนต์พิกเซลของเดิม ยกเว้นใน canvas (วาดเป็นภาพ) |

## 9. คำถามถึง PL

1. D1 — ยอมรับขอบเขตเวทีเกมในข้อ 5 ไหม (กระทบ `UI-01` และกฎ "Tailwind เท่านั้น" ของข้อ 16.0 สำหรับไฟล์ canvas/CSS ของเวที)
2. ผู้สอนเล่นเกมได้ด้วย (ข้อ 4) ตกลงไหม
3. เมนู "โจทย์" ควรอยู่ในระบบนี้ หรือ PL มีแผนให้อยู่ในระบบอื่นของโครงการ
4. ปุ่มหลักของระบบ "ลงรบ" ใต้โลโก้ — เหมาะไหม หรือไม่ต้องมี
