# รอบ 2T — ปล่อยคนเล่นจริงลงสนาม

> สัญญาที่ทุกคนยึดในรอบนี้ | PM เป็นเจ้าของ | 22 ก.ย. 2026

---

## 1. ทำไมรอบนี้สำคัญกว่าการเพิ่มฟีเจอร์

เกมนี้สร้างมาหกรอบแล้ว มีครบตั้งแต่ภาษา เอดิเตอร์ การรบ แผนที่ ไปจนถึงการดวล
แต่มีสิ่งหนึ่งที่ **ยังไม่เคยเกิดขึ้นเลยสักครั้ง: ไม่มีใครเล่นเกมนี้ตั้งแต่ต้นจนจบ**

คำว่า "สมดุลดี" ทุกครั้งที่ผ่านมามาจาก `npm run tune -w engine` ซึ่งเป็นแบบจำลองที่
**เดาโปรแกรมของผู้เล่นไว้เอง** แล้ววัดว่าโปรแกรมที่เดานั้นผ่านชั้นไหนที่เลเวลเท่าไร
มันบอกได้ว่าตัวเลขสอดคล้องกันไหม แต่บอกไม่ได้ว่า **คนจริงจะเขียนโปรแกรมแบบนั้นหรือเปล่า**

รอบนี้จึงไม่เพิ่มอะไรเลย มีแต่การวัด — และวัดสิ่งที่แบบจำลองวัดแทนไม่ได้

## 2. สมมติฐานห้าข้อ (ไม่มีสมมติฐาน = ไม่ใช่การทดสอบ แต่เป็นการเล่นเฉย ๆ)

| # | สมมติฐาน | ถ้าผิดแปลว่าอะไร |
|---|---|---|
| **H1** | ผู้เล่นที่ไม่คิดจะ**ตันจริง** ที่จุดใดจุดหนึ่ง แล้วอัดเลเวลต่อไม่ช่วย | ถ้าเขาจบแผนที่ได้ด้วย `attack()` บรรทัดเดียว **คำสัญญาหลักของเกมเป็นเท็จ** และทุกอย่างที่สร้างมาหกรอบวางอยู่บนสิ่งที่ไม่จริง |
| **H2** | ผู้เล่นที่คิด จะเคลียร์เนื้อหาชุดเดียวกันที่ **เลเวลต่ำกว่า** | ถ้าเลเวลเท่ากัน แปลว่าการเขียนโค้ดดีไม่มีรางวัล เหลือแค่การฟาร์ม |
| **H3** | บทเรียนของโซนเป็นสิ่งที่**จำเป็นต้องใช้จริง** ไม่ใช่ข้อความประดับ | ถ้าผ่านได้โดยไม่ต้องทำตามบทเรียน แปลว่าภูมิภาคเป็นแค่ธีม ไม่ใช่หลักสูตร — ซึ่งเป็นเหตุผลทั้งหมดที่รอบ 2W มีอยู่ |
| **H4** | ข้อความผิดพลาดภาษาไทยพอให้**มือใหม่แก้เองได้** โดยไม่ต้องเปิดคู่มือ | ถ้าไม่พอ เกมสอนเขียนโปรแกรมไม่ได้ ไม่ว่าระบบอื่นจะดีแค่ไหน |
| **H5** | เล่นยาว ๆ หลายร้อยการรบแล้วระบบไม่พัง | ตัวเลข/สถานะเพี้ยนที่โผล่เฉพาะตอนเล่นยาว คือบั๊กที่เทสต์ยูนิตจับไม่ได้ |

## 3. ผู้เล่นสามคน

ทั้งสามเริ่มจากบัญชีใหม่ เลเวล 1 ผู้ฝึกหัด และเล่น **ผ่าน HTTP API เท่านั้น**

### 3.1 `lazy` — คนขี้เกียจ (ตัวควบคุม)
เขียน `attack(weakest(enemies))` ครั้งเดียวแล้ว **ไม่แก้อีกเลยตลอดเกม**
แพ้ที่ไหนก็กลับไปฟาร์มโซนที่ผ่านแล้วเพื่ออัดเลเวล แล้วมาลองใหม่
เลิกเมื่อ **ฟาร์มเพิ่ม 10 เลเวลแล้วยังไม่ผ่านจุดเดิม** — นั่นคือ "กำแพงจริง" ที่ H1 ตามหา

### 3.2 `diligent` — คนตั้งใจ
อ่าน `lessonTh` ของโซนก่อนลง แพ้แล้วดูบันทึกการรบว่าตายยังไง แล้ว**แก้โปรแกรม**
ฟาร์มให้น้อยที่สุดเท่าที่จะทำได้ — เป้าหมายคือผ่านด้วยโค้ด ไม่ใช่ด้วยเลเวล

### 3.3 `newbie` — มือใหม่
**ห้ามอ่าน `docs/bloxcode-language.md` หรือซอร์สของ engine เด็ดขาด**
รู้จัก Python คร่าว ๆ แต่ไม่รู้ว่าเกมนี้รองรับอะไรบ้าง ต้องค้นเอาจาก
สิ่งที่ตัวเกมบอกเท่านั้น: ข้อความผิดพลาด · รายการบล็อกใน `GET /program/catalog` (ถ้ามี) · `lessonTh`
ข้อห้ามนี้คือสิ่งเดียวที่ทำให้ H4 วัดได้จริง ถ้าเขาแอบเปิดคู่มือ ผลที่ได้จะไม่มีความหมาย

## 4. กติกาที่ทำให้ผลเชื่อถือได้

1. **เล่นผ่าน API เหมือนผู้เล่น** — ห้ามแก้ `gamedata.json` ห้ามเรียก `tune.cjs`
   ห้ามอ่านซอร์ส engine เพื่อหาค่าที่ดีที่สุด ห้ามยุ่งกับฐานข้อมูลตรง ๆ
2. **บันทึกทุกการตัดสินใจพร้อมเหตุผล** — "แพ้เวฟ 7 เพราะ MP หมดตั้งแต่เวฟ 5 จึงเพิ่มเงื่อนไข
   ให้ประหยัด MP" ไม่ใช่ "แก้โค้ดแล้วผ่าน" เหตุผลคือข้อมูล ผลลัพธ์คือตัวเลข
3. **ห้ามคุยกันระหว่างสามคน** — `diligent` ห้ามบอกทางลัดให้ `newbie`
4. **รายงานความล้มเหลวให้ละเอียดกว่าความสำเร็จ** ตรงที่ติดคือที่ที่มีข้อมูล
5. ทุกอย่างที่ทำจะถูกบันทึกลงฐานข้อมูลอยู่แล้ว **PM จะตรวจจากฐานข้อมูลเอง**
   ไม่ได้เชื่อรายงานอย่างเดียว — เขียนให้ตรงกับสิ่งที่ทำจริง

## 5. เกณฑ์รับงานของรอบนี้

รอบนี้ "ผ่าน" เมื่อ**ตอบคำถามได้** ไม่ใช่เมื่อผู้เล่นชนะ

| # | เกณฑ์ | วัดยังไง |
|---|---|---|
| T1 | รู้ว่ากำแพงของคนไม่คิดอยู่ตรงไหน (โซน/ความยาก/เลเวลที่ยอมแพ้) | จากฐานข้อมูล ไม่ใช่จากคำบอกเล่า |
| T2 | รู้ส่วนต่างเลเวลระหว่าง `lazy` กับ `diligent` ที่เนื้อหาเดียวกัน | เทียบ `highest_floor` ต่อจำนวนการรบ |
| T3 | มีรายการข้อความผิดพลาดที่ `newbie` แก้เองไม่ได้ | บันทึกของ `newbie` |
| T4 | มีรายการบั๊ก/ค่าที่เพี้ยนที่เจอระหว่างเล่นยาว | ของจริงที่เกิด ไม่ใช่ที่คาดว่าจะเกิด |
| T5 | PM ตรวจฐานข้อมูลแล้วตัวเลขตรงกับรายงานทั้งสามฉบับ | เจอไม่ตรง = รายงานนั้นใช้ไม่ได้ทั้งฉบับ |
