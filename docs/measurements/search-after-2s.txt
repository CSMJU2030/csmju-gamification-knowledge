รอบ 2S — ค้นหาโปรแกรมที่ดีที่สุดจริง: ผล (PM ตรวจเองทุกข้อ 23 ก.ย. 2026)

══════════════════════════════════════════════════════════════════════
คำตอบสั้น
══════════════════════════════════════════════════════════════════════
ในระบบต่อสู้ตอนนี้ **ตรรกะ (if/elif/else) มีค่าน้อยมาก และมีค่าเฉพาะจุดเดียว**

· เกือบทุกที่: โปรแกรมหลายบรรทัดที่ดีที่สุด ประหยัดเลเวลได้ 0-1 เทียบกับบรรทัดเดียวที่ดีที่สุดของโซนนั้น
· สิ่งที่มีค่าจริงคือ **เลือกบรรทัดเดียวให้ถูกโซน** — ใช้สกิลหรือตีธรรมดา · เล็งตัวไหน
  (นักรบที่ภูเขาไฟ: attack(weakest) ต้องเลเวล 15-20 · power_strike ใส่ตัว deadliest ต้องแค่ 7-12)
· จุดเดียวที่ตรรกะมีค่า: **ภูเขาไฟรอบ 4-5 สำหรับจอมเวทและผู้พิทักษ์ +2 เลเวล**
  เพราะมีสกิลฟื้นฟู/โล่ และภูเขาไฟมีสองจังหวะ (มอนอันตรายยังอยู่ / ไม่อยู่)

══════════════════════════════════════════════════════════════════════
ผลการค้นรอบแรกของ PM ผิด — เกณฑ์ S2 จับได้
══════════════════════════════════════════════════════════════════════
PM สรุปรอบแรกว่า "ตรรกะมีค่าศูนย์ทุกที่ ทุกอาชีพ"
เอเจนต์อิสระที่ได้รับคำสั่งให้ล้มข้อสรุปนี้ ล้มได้สองในสามอาชีพ และ PM วัดซ้ำเองแล้วตรงทุกตัว:

  ผู้พิทักษ์  if count(enemies) >= 2: attack(deadliest(enemies))  else: cast("barrier", me)
              ภูเขาไฟรอบ 4 +1 · รอบ 5 +2   (PM วัดเอง: ตรง)
  จอมเวท     โปรแกรม for นับมอนอันตราย แล้วฟื้นฟูเฉพาะตอนปลอดภัย
              ภูเขาไฟรอบ 4 +2 · รอบ 5 +2   (PM วัดเอง: ตรง)
  นักรบ      ล้มไม่ได้ — ดีสุด +1 (ไม่มีสกิลฟื้นฟู และการกระทำที่ถูกเหมือนกันทุกสถานการณ์)

**บั๊กในเครื่องมือของ PM ที่ทำให้พลาด** — รอบคัดกรองวัดที่เลเวลต่ำ ซึ่งสกิลที่ปลดช้ายังบันทึกไม่ได้
(barrier lv6 · heal lv7 · execute lv10) ทุกโปรแกรมที่ใช้สกิลพวกนี้ได้ 0 แล้วตกรอบ
โปรแกรมผู้พิทักษ์ข้างบนอยู่อันดับ 814 จาก 1,430 · และช่องตัวแทนส่วนใหญ่อยู่เลเวล 1 ที่อะไรก็ชนะ
→ **เครื่องมือมองไม่เห็นสกิลที่มีค่าขึ้นกับสถานการณ์ ซึ่งคือสกิลที่ทำให้ตรรกะมีค่าพอดี**
แก้แล้ว: คัดกรองด้วยเลเวลขั้นต่ำจริง (ตัวชี้วัดเดียวกับผลจริง) · seed เพิ่มจาก 24 เป็น 64
(เอเจนต์วัดได้ว่า 24 seed แกว่ง ±1 เลเวล ผล +2 สองตัวของมันเองลดเหลือ +1 เมื่อเปลี่ยน seed)

══════════════════════════════════════════════════════════════════════
ทำไมตรรกะถึงไร้ค่า — กติกาเจ็ดข้อ (PM ยืนยันจากโค้ดจริงทุกข้อ)
══════════════════════════════════════════════════════════════════════
นี่คือโจทย์ของรอบถัดไป — แต่ละข้อคือคันโยกที่วัดผลได้ด้วยเครื่องมือนี้

1. **cast ทุกตัวมี if ในตัวให้ฟรี** — MP ไม่พอ → ข้ามโดยไม่เสียเทิร์น แล้วตีธรรมดาแทน
   บรรทัดเดียว cast(...) จึงเท่ากับ "ร่ายถ้าได้ ไม่งั้นตี" อยู่แล้ว (evaluator.ts บรรทัด 8-9)
   กติกานี้ตั้งใจให้ใจดีกับมือใหม่ แต่มันลบเหตุผลอันดับหนึ่งที่จะเขียนเงื่อนไข
2. **หนึ่งโซนมีตัวอันตรายแบบเดียว และตัวเลือกเป้าที่มีอยู่แล้วหาเจอเอง**
   (ภูเขาไฟ: deadliest = ยักษ์ · ซากปรักหักพัง: weakest = จอมเวทศัตรู) — การเล็งเหลือแค่เลือกคำ
3. **มอนที่ไม่ใช่ตัวอันตรายตีได้แค่ 1** (ดาเมจขั้นต่ำ 1 ใน types.ts) — การตัดสินใจเหลือข้อเดียว:
   "ตัวอันตรายยังอยู่ไหม"
4. **MP ของจอมเวทไม่เคยขาด** — firebolt 7 · ฟื้น 6-10 ต่อเทิร์น ไม่มีอะไรให้ต้องประหยัด
5. **มอนไม่มีสถานะให้ตอบสนอง** — ทุกตัวใช้โปรแกรมเดียวกัน · `debuffs: []` ฮาร์ดโค้ด (battle.ts 260)
   **has_debuff() มีอยู่ในภาษาแต่ไม่มีวันเป็นจริง**
6. **สกิลที่มีค่าขึ้นกับสถานการณ์ปลดช้า** — barrier lv6 · heal lv7 · execute lv10
   เขียนชื่อสกิลนี้ที่ไหนก็ตาม ทั้งโปรแกรมบันทึกไม่ได้ก่อนเลเวลนั้น → ครึ่งแรกของเกมไม่มีเหตุผลให้เขียน if
7. **จุดตัดความเร็วตัดสินมากกว่าโค้ด** — จอมเวทภูเขาไฟรอบ 5: เลเวล 8 ยักษ์ได้ตีก่อนทุกตัว เลเวล 9 ครึ่งต่อครึ่ง

══════════════════════════════════════════════════════════════════════
ข้อดีที่ซ่อนอยู่
══════════════════════════════════════════════════════════════════════
· บทเรียนภูเขาไฟ ("deadliest คือเงื่อนไขผ่าน") **จริง** — บรรทัดเดียวที่ชนะภูเขาไฟคือ
  power_strike ใส่ตัว deadliest/strongest แค่มันสอนการเลือกเป้า ไม่ได้สอนตรรกะ
· จุดที่ตรรกะมีค่า (+2) บอกสูตรของสถานการณ์ที่ทำให้โค้ดมีค่า:
  **มีจังหวะที่ต่างกัน + มีสกิลที่ถูกหรือผิดขึ้นกับจังหวะ + บรรทัดเดียวแยกจังหวะไม่ออก**
  นี่คือแบบร่างของมอนกลไกที่รอบหน้าควรสร้าง

เกณฑ์ S4 (ยืนยันตารางล็อกรายภูมิภาคบนเซิร์ฟเวอร์จริง) — ตั้งใจไม่ทำ
══════════════════════════════════════════════════════════════════════
ผลของรอบนี้ทำให้ S4 ไม่มีความหมาย: ในช่องที่ค่าของโค้ดเป็น 0 ไม่มีเลเวลล็อกไหนสร้างกำแพงได้
เพราะบรรทัดเดียวที่ถูกโซนทำได้เท่าโปรแกรมที่ดีที่สุดพอดี — ล็อกต่ำ ทั้งคู่ตาย · ล็อกสูง ทั้งคู่ผ่าน
การล็อกเลเวลจะมีประโยชน์ **หลัง** จากที่กลไกของมอนทำให้ค่าของโค้ดขึ้นมาจากศูนย์แล้วเท่านั้น

ข้อเสนอสำหรับรอบถัดไป
══════════════════════════════════════════════════════════════════════
สร้างกลไกมอนที่แก้กติกาเจ็ดข้อข้างบน **โดยใช้ "ค่าของโค้ด" จากเครื่องมือนี้เป็นเกณฑ์รับงาน**
เปลี่ยนกลไกหนึ่งอย่าง → รัน progsearch → ค่าของโค้ดขึ้นไหม · ไม่ขึ้น = กลไกนั้นไม่ได้ช่วย ถอดออก
สูตรจากจุดเดียวที่ตรรกะมีค่า: มีจังหวะต่างกัน + มีการกระทำที่ถูก/ผิดตามจังหวะ + บรรทัดเดียวแยกจังหวะไม่ออก
